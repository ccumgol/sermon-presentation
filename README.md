# Sermon Presentation

OBS Studio의 **브라우저 소스**로 성경 본문과 찬양 가사를 송출하는 로컬 애플리케이션.

- 성경 12개 역본 내장 (한국어 7종 · 영어 3종 · 헬라어 · 히브리어)

- **교독문 두 벌** — 통일찬송가용 76편 / 새찬송가용 137편 (번호가 같아도 다른 글)

## 설치와 실행

```bash
npm install
```

성경 DB를 빌드합니다. 원본 12개 파일(SQLite 11 + JSON 1)을 읽어 `data/bible.sqlite` 하나로 합칩니다.
원본은 **읽기 전용으로만** 열기 때문에 절대 변경되지 않습니다.

```bash
npm run bible:build
```

빌드 결과를 검증합니다. 원본과 무작위 200절을 직접 대조하는 등 47개 항목을 확인합니다.

```bash
npm run bible:verify
```

### 매주 쓰는 방법 — 한 줄

```bash
./start.sh
```

컨트롤 패널을 빌드하고, 서버를 띄우고, **브라우저까지 열어 줍니다.**
터미널 어디서나 `presentation` 으로 부를 수 있습니다(`~/.zshrc` 의 alias).

> ⚠️ alias 를 바꾼 뒤에는 **새 터미널**을 열어야 합니다. 이미 열려 있던 셸은 옛 alias 를
> 그대로 들고 있습니다(`source ~/.zshrc` 로도 됩니다).

이미 서버가 떠 있으면 **두 번째 서버를 몰래 띄우지 않고 먼저 묻습니다** — 그대로 쓸지,
껐다 새로 시작할지. (옛 프로세스가 구버전 코드로 응답하는 함정을 막습니다 —
[문제 해결 2.7](docs/TROUBLESHOOTING.md))

| 부르는 법 | 하는 일 |
|---|---|
| `presentation` · `./start.sh` | 이 PC 안에서만 (기본·권장) |
| `presentation lan` · `./start.sh lan` | 태블릿으로도 조작 — **접속 암호를 넣어야 한다** |
| `PORT=7800 ./start.sh` | 포트를 직접 준다 |
| `OPEN_BROWSER=0 ./start.sh` | 브라우저를 열지 않는다 |

종료는 `Ctrl+C` 입니다.

### 직접 실행 (스크립트를 쓰지 않을 때)

```bash
npm start
```

브라우저에서 http://localhost:7777 을 열면 컨트롤 패널이 나옵니다.
7777이 점유되어 있으면 다음 포트를 자동으로 잡고, 실제 포트를 로그와 화면에 표시합니다.

**기본은 이 PC 안에서만 열립니다.** 태블릿·다른 기기로 조작하려면 그때만 엽니다.

```bash
npm run start:lan
```

**태블릿은 접속 암호를 넣어야 합니다.** 암호가 정해지지 않았으면 서버가 LAN 으로 뜨기를
거부합니다(`./start.sh lan` 은 그 자리에서 정하게 해 줍니다).

```bash
npm run password              # 암호를 정한다 (화면에 찍히지 않는다)
npm run password -- --show    # 정해져 있는지 본다
npm run password -- --clear   # 없앤다 (그러면 LAN 을 열 수 없다)
```

| | |
|---|---|
| **이 PC** (컨트롤 패널·OBS·강사 모니터·프로젝터) | 암호를 **묻지 않습니다** |
| **태블릿·다른 기기** | 처음 열 때 한 번 넣고, **30일간 기억**합니다 |

이 PC 를 면제하는 것은 편의가 아니라 필요입니다 — **OBS 브라우저 소스는 암호를 입력할 수
없습니다.** 다른 PC 의 OBS 처럼 암호를 넣을 수 없는 기기가 LAN 에 있으면 그 주소만
면제합니다: `SERMON_TRUSTED_IPS=192.168.1.50 ./start.sh lan`

암호를 잊으면 `npm run password` 로 다시 정하면 됩니다(평문으로 저장되지 않습니다).
다시 정하면 **접속해 있던 기기가 모두 로그아웃**됩니다.
자세한 내용은 [보안 감사](docs/SECURITY-AUDIT.md).

개발 중에는 패널과 서버를 함께 감시 모드로 돌립니다.

```bash
npm run dev
```

## OBS 설정

1. 소스 추가 → **브라우저**
2. URL: `http://localhost:7777/output/?layer=main`
3. 폭 `1920` / 높이 `1080`
4. 사용자 지정 CSS 칸을 **비웁니다** (기본값 삭제 — 안 지우면 배경이 덮여 투명이 깨집니다)
5. ☐ 표시되지 않을 때 소스 종료 → **해제**
6. ☐ 장면이 활성화될 때 브라우저 새로고침 → **해제**

크로마키 필터는 필요하지 않습니다. 페이지가 알파 투명으로 합성되므로 글자 경계가
깨끗하고, 반투명·그림자 효과도 그대로 나옵니다.

### ⚠️ 앱을 새 버전으로 올린 뒤에는 OBS 소스를 새로고침하세요

출력 페이지(`public/output/`)가 바뀌면 **OBS 브라우저 소스를 한 번 새로고침해야** 새 기능이
나옵니다. **서버 재시작만으로는 부족합니다** — OBS 안의 페이지는 WebSocket 만 자동으로
다시 붙고 JS 는 메모리에 있던 옛 판 그대로입니다. 위 6번(장면 활성화 시 새로고침)을
꺼 두었기 때문에 저절로 갱신되지도 않습니다.

> 브라우저 소스 더블클릭 → **`현재 페이지 새로고침`**

새로고침해도 화면은 복구됩니다. 접속 즉시 서버가 현재 상태를 보내므로 잠깐 깜빡인 뒤
송출 중이던 내용이 그대로 다시 뜹니다.

옛 판이 떠 있으면 **새로 생긴 슬라이드 종류를 만났을 때 화면이 바뀌지 않습니다.**
출력 페이지는 모르는 내용을 받으면 **화면을 비우지 않고 이전 내용을 유지**하도록 만들어져
있어서(예배 중 검은 화면 방지), 검은 화면 대신 "안 바뀜"으로 나타납니다.

### 확인용 링크

| URL | 용도 |
|-----|------|
| `/output/?demo=1&preview=1` | 샘플 본문 + 체커보드 배경 (합성 결과 확인) |
| `/output/?demo=1` | 샘플 본문 + 투명 배경 |
| `/output/?debug=1` | 빈 화면 + 진단 배지 |

`preview`와 `debug`는 쿼리 파라미터를 붙였을 때만 나타나므로, 실제 송출 화면에는
절대 표시되지 않습니다.

|--------|------|

화살표는 슬라이드 단위, PgDn·PgUp은 예배 순서 항목 단위로 움직입니다.
경계에서 순환하지 않습니다 — 마지막에서 처음으로 돌아가면 예배 중 사고입니다.
입력창에 포커스가 있을 때는 단축키가 동작하지 않습니다.

## 템플릿

위치·글자 크기·색상·외곽선·배경을 **템플릿** 탭에서 편집합니다. 값을 만지면 송출
화면에 즉시 반영되고(저장 전), '저장'을 눌러야 DB에 남습니다. 예배 중 실수로 만진
것이 영구화되지 않게 한 구조입니다.

**원어 폰트.** 헬라어·히브리어는 언어별 폰트 체인을 따로 씁니다. 전용 폰트(SBL Greek,
SBL Hebrew 등)가 설치돼 있으면 그것을 쓰고, 없으면 Times New Roman 으로 내려갑니다.

체인 끝을 `serif` 같은 총칭 키워드로만 두면 안 됩니다 — 총칭 폰트가 다음절 헬라어
(`Ἐ` `ῇ` `ἦ`)를 덮지 못하면 브라우저가 **글자마다** 다른 폰트로 대체해 자간이
들쭉날쭉해집니다. 실측으로 같은 구절이 819.6px 대 526.6px 로 벌어졌습니다.
그래서 총칭 앞에 어느 PC 에나 있는 폰트를 둡니다.

이미 저장한 템플릿 사본에 옛 체인이 남아 있으면 앱을 켤 때 자동으로 올립니다.
직접 고르신 폰트는 문자열이 다르므로 건드리지 않습니다.

내장 프리셋 8종(하단·전체·좌우 — 셋 다 성경·찬송 겸용 · 로우서드 · 순서 표시 · 교독문 ·
전례문 · 공백)은 **덮어써도 원본이 남습니다**. 값을 바꿔 저장하면 그 프리셋 위에 '고친 값'이
얹히고, **원본으로 되돌리기**로 언제든 돌아갑니다 (사본이 늘어나지 않습니다).

**화면 넘김**은 기본이 **'1절씩'** 입니다. 설교 본문은 한 절씩 짚어 가며 읽는 경우가
많아, 화살표 한 번에 한 절씩 넘어가는 편이 예측 가능합니다.

'자동'을 고르면 실제 출력 페이지를 1920×1080 크기의 숨긴 iframe으로 띄워 재고,
넘치기 직전까지 절을 담습니다. 글자 수로 추정하지 않는 이유는 폰트·자간·행간·여백이
모두 얽혀 있어 추정이 반드시 틀리기 때문입니다. 그래도 한 절이 화면을 넘기면 출력
페이지가 배율로 줄여 담습니다(최소 배율 지정 가능).

## 성경 참조 입력

참조 입력은 다양한 표기를 받습니다.

```
요 3:16      요3:16      요한복음 3장 16절     요 3.16      Gen. 1:1
시 23        시편 23편    창 1-2               요 3:16-4:2   롬 8:28-30
1요 2:1      요일 2:1     I Samuel 3:1         Song of Songs 2:1
마 5:3-12; 6:9-13        요 3:16,18           ㅇㅎㅂㅇ 3:16 (초성)
```

책 이름이 여러 곳에 걸리면 추측하지 않고 후보 버튼을 보여줍니다.

### 설계 원칙

**출력 페이지는 의존성 0을 유지합니다.** React·CDN·외부 폰트를 쓰지 않습니다.
OBS 내장 브라우저(CEF)에서 초기화가 실패할 지점을 없애기 위한 의도적 제약입니다.

**경로를 하드코딩하지 않습니다.** 모든 경로는 `server/paths.ts`를 거칩니다.
Electron 패키징(Phase 6) 때 `SERMON_DATA_DIR` 하나만 지정하면 됩니다.

**본문은 임의로 수정하지 않습니다.** 표시용 정제로 달라진 절은 `verses.text_raw`에
원문을 남겨 언제든 대조할 수 있습니다. 검증기가 무작위 표본을 원본과 직접 비교합니다.

**화면을 스스로 비우지 않습니다.** 서버가 죽거나 연결이 끊겨도 출력 페이지는
마지막 내용을 유지하고 재연결만 시도합니다. 예배 중 검은 화면이 나가는 것이
최악의 결과이기 때문입니다. 상태는 모든 변경마다 디스크에 남아 서버를 재시작해도
마지막 화면으로 복구됩니다.

**미리보기와 송출 화면이 같은 코드입니다.** 컨트롤 패널의 미리보기는 실제 출력
페이지를 iframe으로 띄운 것입니다. 별도 렌더러를 두면 "미리보기에선 괜찮았는데
화면에선 다르다"가 생깁니다.

## 예배 순서

**예배 순서** 탭에서 찬양·본문·광고를 순서대로 담아 두고, 예배 때 **한 번 올려** 처음부터
끝까지 진행합니다. 순서표는 항목 목록(`CueItem[]`)으로 저장되고, 올릴 때 각 항목을 덱으로
풀어 **하나의 평평한 덱**으로 합칩니다.

### 예배 유형과 저장

순서표를 날짜별로 새로 만들지 않습니다. **주일예배·수요예배·새벽기도회·부흥회** 같은
**유형**을 두고 매주 그것을 고쳐 씁니다. 처음 실행하면 이 네 가지가 들어 있고, 필요 없으면
지우거나 ＋ 로 더하면 됩니다.

| 버튼 | 동작 |
|------|------|
| **템플릿 업데이트** | 지금 고친 내용을 그 **유형의 원본**으로 굳힙니다 (앞으로 계속 쓸 순서) |
| **순서 저장하기** | 이번 회차를 따로 남깁니다 (이름 기본값 = `날짜 + 유형 이름`) |
| **순서 불러오기** | 저장해 둔 회차를 다시 엽니다 |

같은 이름으로 저장하면 버튼이 **'덮어쓰기'** 로 바뀌고 경고가 뜹니다. 저장하지 않은 변경이
있는 상태에서 다른 것을 열면 확인을 받습니다.

### 항목 종류

| 아이콘 | 종류 | 설명 |
|--------|------|------|
| 📖 | 성경 | 참조를 입력하면 **추가하기 전에** 파싱 결과를 보여줍니다 |
| 🎵 | 찬양 | 번호·제목으로 찾아 고릅니다 |
| 📋 | **순서 표시** | 대표기도·주기도문·사도신경·설교 제목·축도처럼 **지금 무슨 순서인지**를 띄웁니다 (아래 참고) |
| 📝 | 광고 | 여러 줄로 쓰면 그대로 나갑니다 |
| 💬 | 인용구 | 설교 중 잠깐 띄웠다 `↩ 직전으로` 로 되돌립니다 |
| ⬛ | 공백 | 화면의 **글자를 지웁니다**. `B`(블랙)와 다릅니다 — 블랙은 내용을 남긴 채 숨겨 즉시 복구하는 것이고, 공백은 내용이 없는 슬라이드입니다. 템플릿 배경(그림·동영상)은 그대로 남습니다 |
| ▾ | 구분 | 그룹 머리글 — **화면에 나가지 않습니다** |

광고·인용구·순서 표시는 **Enter 로 추가**되고, 줄바꿈은 `Shift+Enter` 입니다.
순서 표시는 자주 쓰는 이름 10종을 버튼으로 바로 넣을 수 있습니다.

### 순서 표시 배치

**첫 줄이 순서 이름, 다음 줄이 담당자**입니다.

```
대표기도
박기현 목사
```

기본은 **좌우**입니다 — 왼쪽에 순서 이름, 오른쪽에 담당자를 놓고 담당자 아래에 밑줄을
긋습니다. 밑줄은 이름보다 넓어서 '적어 넣는 칸'처럼 보입니다.

```
 대표기도                                    박기현 목사
                                          ─────────────
```

- 담당자 줄이 없으면 오른쪽 칸과 밑줄을 **만들지 않습니다** (`주기도문` 처럼 이름만 띄울 때)
- 담당자를 여러 줄로 적으면 한 줄로 합쳐 오른쪽에 넣습니다
- 항목을 고른 뒤 **배치**를 `쌓기`로 바꾸면 줄을 그대로 위아래로 쌓습니다

### 항목마다 조정할 수 있는 것

순서 표시 항목을 고르면 목록 아래 설정에서 조정합니다. **지정하지 않으면 템플릿 값**을 씁니다.

| 조정 | 설명 |
|------|------|
| **담당자 크기** | 템플릿의 보조 텍스트 크기에 대한 배수. 이름이 길어 한 줄에 안 들어가는 항목만 줄일 때 |
| **테두리** | 순서·담당자의 외곽선 두께(px). `0` 이면 그 항목만 테두리를 끕니다. `↺` 로 템플릿 값 복귀 |
| **글자 조정** | 글자 하나씩 크기·높낮이를 직접 지정. 만진 글자만 자동 리듬을 벗어납니다 |

셋 다 **단독 송출 중이면 슬라이더를 움직이는 즉시 화면이 따라옵니다.**
순서표 전체를 올린 뒤에는 반영되지 않습니다 — 예배 중 덱이 통째로 바뀌면 진행 위치를
잃기 때문입니다. 조정한 뒤 **'예배용으로 올리기'를 다시** 누르면 반영됩니다.

위치·글자 크기·색은 **템플릿**을 따릅니다. 내장 프리셋 **'순서 표시 — 명조 리듬'** 을 그
항목의 템플릿으로 지정하면 아래 두 가지가 함께 적용됩니다.

### 글자 리듬

제목을 **글자마다 크기와 높이를 달리해** 붓글씨처럼 보이게 합니다. 어절 안에서 **양끝은
크게, 가운데는 작게** 두고 작아진 글자를 조금 내립니다. 띄어쓰기를 만나면 리듬을 처음부터
다시 타므로 `찬양과 / 경배` 의 뒤 어절 첫 글자가 다시 커집니다.

어절의 **첫 글자부터 네 글자까지** 아래 값을 따릅니다. 띄어쓰기를 만나면 처음부터
다시 시작합니다.

| 순서 | 크기 | 높낮이 |
|------|-----:|-------:|
| 첫째 | 100% | 0 |
| 둘째 | 96% | ↑19% |
| 셋째 | 90% | ↓10% |
| 넷째 | 90% | ↑5% |

`예배부름`(4자)이 기준이고 `축도`(2자)·`축복송`(3자)은 **앞 두세 글자를 그대로** 따릅니다.

**다섯째 글자부터는 자동이 손대지 않습니다**(기본 크기). `찬양과경배` 처럼 `XX와XX` 꼴은
이름마다 어울리는 모양이 달라 자동으로 정하면 어색해지기 때문입니다. 그런 이름은
**글자 조정**에서 직접 맞추면 되고, 조정 화면이 "자동은 앞 4글자까지"라고 알려 줍니다.

**템플릿** 탭 → 표시 옵션에서 **크기와 높낮이를 따로** 조절합니다.

| 값 | 뜻 |
|------|------|
| **글자 리듬** | 크기 흔들림 (0 = 모든 글자 같은 크기) |
| **글자 높낮이** | 작아진 글자를 얼마나 내릴지 (0 = 아랫선 가지런히) |

크기만 흔들거나, 크기는 그대로 두고 높낮이만 흔들 수도 있습니다.

무작위가 아니라 **정해진 규칙**이라 같은 제목은 언제나 같은 모양입니다. 무작위로 두면
새로고침할 때마다 배치가 달라져 같은 순서가 예배마다 다르게 나갑니다.

### 명조 서체

기본 체인은 `Noto Serif KR → 바른바탕 Pro → 나눔명조 → 애플명조 → Batang → serif` 입니다.
**설치된 것 중 앞에 있는 것**이 쓰입니다.

폰트 이름은 적어 넣은 대로 잡히지 않는 일이 잦습니다 — 파일 이름이 `BareunBatangOTFPro-3.otf`
라고 `"BareunBatangOTFPro 3"` 으로 적으면 **어디에도 안 걸려 조용히 고딕으로 대체**됩니다.
그래서 템플릿 탭의 폰트 칸 아래에 **실제로 쓰이는 폰트**를 표시합니다.

> 실제 사용: **BareunBatangOTFPro** · 없는 폰트: Noto Serif KR

총칭(`serif`)까지 떨어지면 빨간 글씨로 알립니다 — 그 경우 글자마다 다른 폰트로 대체돼
자간이 들쭉날쭉해질 수 있습니다.

- 화살표로 슬라이드를 넘기면 항목 경계를 자연히 넘어갑니다
- `PgDn`·`PgUp`으로 항목 단위 점프
- 성경 항목은 올릴 때 실측 자동 분할을 거칩니다 — 예배 중 다시 계산하지 않습니다
- 풀지 못한 항목은 **건너뛰되 반드시 알립니다.** 예배 중 순서가 조용히 하나
  사라지는 것이 가장 위험합니다

슬라이드를 미리 만들어 저장하지 않는 이유는, 템플릿을 바꿨을 때 순서표가 낡지 않게
하기 위함입니다.

### 예배 전 안내 (자동 진행)

예배 시작 전 안내 화면을 자동으로 넘겨 둘 수 있습니다. **구분**을 하나 만들고 그 아래에
광고·순서 표시·성경 등을 담은 뒤, 구분을 골라 **예배 전 안내 (자동으로 넘김)** 를 켭니다.

- 기본 **8초**마다 넘어가고, 마지막에서 **처음으로 돌아갑니다**
- 저절로 시작되지 않습니다 — 목록에서 그 구분의 **▶** 를 눌러야 시작합니다
- **다른 항목을 송출하거나 '예배용으로 올리기'를 누르면 즉시 멈춥니다.**
  예배가 시작됐는데 화면이 저절로 넘어가는 것이 가장 위험하기 때문입니다
- 돌고 있는 동안 노란 띠와 **■ 정지** 버튼이 계속 보입니다

예배 순서 자체(예배 중 덱)는 마지막에서 순환하지 않습니다. 순환은 **예배 전** 구간만입니다.

## 배경 그림 · 반복 동영상

카메라 영상 없이 프로젝터에만 띄우는 예배라면, 투명 배경 대신 **그림이나 반복 동영상**을
깔 수 있습니다. **템플릿** 탭 → 배경 → `그림` 또는 `반복 동영상`.

파일을 넣는 방법은 두 가지이고 둘 다 됩니다.

| 방법 | 설명 |
|------|------|
| 폴더에 직접 | `data/backgrounds/` 에 넣고 **새로 고침** |
| 앱에서 올리기 | 템플릿 탭의 파일 선택 (한 파일 **64MB** 까지) |

- 그림: `jpg` `png` `webp` `gif` `avif` · 동영상: `mp4` `webm` `mov` `m4v`
- **맞춤**(화면 채우기 / 전체 보이기)과 **불투명도**를 조절합니다
- 배경은 템플릿마다 지정합니다 — 설교 본문과 찬양에 다른 배경을 줄 수 있습니다
- 파일이 없거나 못 읽어도 **화면을 비우지 않습니다.** 배경만 빠지고 컨트롤 패널에 알립니다
- 동영상은 소리 없이 반복 재생됩니다 (브라우저가 음소거일 때만 자동 재생을 허용합니다)

**배경 파일은 데이터 이전(백업)에 담기지 않습니다.** 동영상이 수백 MB라 이전 파일을 못 쓰게
만들기 때문입니다. 다른 PC로 옮길 때는 `data/backgrounds/` 폴더째 복사하세요.

## OBS 없이 쓰기

OBS는 **카메라 영상 위에 자막을 얹을 때** 필요합니다. 카메라 없이 프로젝터에만 띄우는
예배라면 지금도 OBS 없이 됩니다.

1. **템플릿** 탭에서 배경을 `단색·반투명 띠`(검정, 불투명도 1) 또는 위의 `그림`/`반복 동영상`으로
2. 출력 페이지 `http://localhost:7777/output/?layer=main` 를 프로젝터 화면의 브라우저 창으로 열고
3. **F11**(맥은 `⌃⌘F`)로 전체화면

컨트롤 패널은 다른 창이나 다른 기기(태블릿)에서 조작하면 됩니다. 별도 프로그램은 필요 없습니다.
전용 앱 창(모니터 지정·항상 위)은 Phase 6 Electron 패키징에서 함께 판단합니다.

## 데이터 이전

**설정** 탭 → 데이터 이전에서 찬양·템플릿·예배 순서·설정·폰트를 파일 하나로 내보내고
가져옵니다. 다른 봉사자 PC에 설치할 때 쓰는 경로입니다.

`.zip`이 아니라 **JSON 한 파일**입니다 — Node에 zip이 내장돼 있지 않아 의존성이 늘고
Electron 패키징에서 변수가 되는 것을 피했고, 사람이 열어 내용을 확인·수정할 수 있는 편이
예배 전 급할 때 실제로 유용합니다. 폰트는 base64로 함께 담깁니다.

성경 DB(97MB)는 담기지 않습니다 — 원본에서 다시 빌드하면 됩니다.
송출 상태도 담기지 않습니다 — 다른 PC에서 복원하면 엉뚱한 화면이 뜹니다.

가져오기는 **추가**가 기본입니다. **덮어쓰기**는 기존 찬양·템플릿·순서를 모두 지우므로
명시적으로 고르고 한 번 더 확인해야 실행됩니다.

## 찬양 자료 폴더

곡집 자료는 **파일로 두고, sqlite 는 앱이 만드는 산출물로** 둡니다. 성경 DB 와 같은
구조입니다 — 원본은 읽기 전용으로만 열고 `data/songs.sqlite` 를 빌드합니다.

파일을 원본으로 두는 이유는 **수동 보정** 때문입니다. 자료를 모으는 중에는 편집기로
바로 고칠 수 있어야 하고, git 으로 "어느 가사를 고쳤는지" 이력이 남아야 합니다.
sqlite 를 원본으로 두면 둘 다 어렵습니다.

폴더 규약은 현재 수집 구조를 그대로 채택했습니다.

```
~/Desktop/Data/Praise/
├── 찬미예수 2000/                 ← 폴더 이름 = 곡집 이름
│   ├── 1 나를 사랑하는 자들이.txt   ← 「번호 제목」 = 곡
│   ├── 10 주님앞에 나와서.txt
│   └── _book.md                   ← (선택) 곡집 메타: 대표 글자·번호 체계
└── 찬미예수 2000 악보/             ← 이름에 '악보' 가 붙으면 악보 폴더
    ├── 0001.bmp                   ← 번호로 가사와 잇습니다
    └── (1889).bmp                 ← 두 형식을 모두 받습니다
```

`.txt` 와 `.md` 를 함께 받습니다. 저작권·CCLI 같은 메타가 필요한 곡만 md 로 올리면
되고, 나머지는 txt 그대로 둬도 됩니다.

가져오기 전에 점검합니다. **원본을 고치지 않고 목록만** 만듭니다.

```bash
npm run praise:check
```

번호 중복·빠진 번호·제목 없는 파일·내용이 거의 없는 파일·악보 짝을 보고합니다.

**원본에 줄바꿈이 있으면 그대로 씁니다.** 자료 제공자의 줄나눔이 추정보다 정확하므로
`lines_source = imported` 로 표시해 자동 정렬 대상에서 뺍니다. 찬송가 DB 에는 줄바꿈이
없어 추정해야 했지만, 수집 자료는 대개 줄바꿈을 갖고 있습니다.

## 찬양 · 곡집

곡은 **곡집(시리즈)** 단위로 관리합니다. 새찬송가·통일찬송가가 내장돼 있고,
'많은 물소리'·'찬미2000' 같은 복음성가 시리즈를 얼마든지 추가할 수 있습니다.

**찬송가의 '장'과 복음성가의 '번호'는 같은 항목**(`number`)입니다. `기타` 곡집은
번호 체계가 없어 번호 없이 곡을 담을 수 있습니다.

### 찾기

| 입력 | 동작 |
|------|------|
| `305` | 모든 곡집에서 305번을 찾습니다 (새305 · 통305 · 물305 …) |
| `새 305` `통 405` `물 42` | 곡집을 지정합니다 (대표 글자 또는 이름 앞부분) |
| `나같은죄인` | 제목 — 공백을 무시합니다 |
| `광명을 얻었네` | 가사 부분일치 + 걸린 대목 표시 |

**바로가기 버튼 4개**(대표 한 글자)로 곡집을 즉시 바꾸고, 그 밖의 곡집은 드롭다운에서
고릅니다. 곡집을 고르면 그 곡집의 번호 순 목록이, `전체`를 누르면 통합 검색 결과가
리스트로 나옵니다.

화면은 **2단**입니다 — 왼쪽에서 곡을 고르고 오른쪽에서 표시 언어·화면 넘김을 정합니다.
검색 결과 목록은 창 높이에 맞춰 늘어나고, 페이지가 아니라 **목록만** 스크롤합니다.
창이 좁으면(900px 미만) 위아래로 쌓입니다.

### 즐겨찾기

검색창이 비어 있으면 **즐겨찾기 5곡**이 칩으로 나옵니다. 눌러서 바로 송출합니다.

곡을 열고 제목 왼쪽의 **☆** 를 누르면 즐겨찾기에 들어갑니다. 송영·봉헌송처럼 예배마다
쓰는 곡을 넣어 두면 검색 단계가 없어집니다.

최근 송출 순으로 두지 않은 이유는 **목록이 매번 흔들리기 때문**입니다. 늘 같은 자리에
있어야 손이 기억합니다. 아직 지정한 곡이 없으면 **자주 쓴 곡**을 대신 보여 주고,
라벨로 그 사실을 알립니다.

### 번호 즉시 송출

검색창에서 **Enter** 를 누르면 첫 번째 결과를 열고 **곧바로 송출**합니다.
`새 305` → Enter 로 끝나므로, 예배 중 곡이 갑자기 바뀌어도 손이 멈추지 않습니다.

곡을 여는 것과 송출을 한 동작으로 묶었습니다. 결과가 없으면 아무 일도 일어나지
않습니다 — 잘못 눌러 화면이 비는 일은 없습니다.

### 사용 기록

즐겨찾기와 별개로 송출 기록이 쌓이며, 즐겨찾기가 비었을 때의 대체 목록과 검토 화면의
'자주 쓴 곡 순' 정렬에 쓰입니다.

- 기록은 **덱이 실제로 만들어졌을 때만** 남습니다 (가사가 없어 빈 덱이면 기록하지 않습니다)
- 순서는 시각이 아니라 **단조 증가 순번**(`used_seq`)으로 잡습니다. 같은 밀리초에 두 곡을
  보내거나 시스템 시계가 뒤로 가도 순서가 뒤집히지 않습니다
- 기록에 실패해도 송출은 그대로 진행됩니다 — 편의 기능이 예배를 막아서는 안 됩니다

### 가사 점검

**곡집 관리 → 가사 점검**은 송출할 수 없는 곡을 찾아 목록으로 보여줍니다.
곡집별로 범위를 좁힐 수 있습니다.

| 표시 | 뜻 |
|------|-----|
| 섹션 없음 | 번호·제목만 있고 가사가 아예 없음 |
| 가사 없음 | 섹션은 있으나 줄이 없음 |
| 한 줄뿐 | 제목만 들어간 것으로 보임 |

점검은 **아무것도 지우지 않습니다.** 자료를 일부만 가져왔을 때 무엇이 비었는지
확인하는 용도이고, 채우는 것은 사람의 판단입니다.

### 후렴 처리

**후렴은 각 절 뒤에 붙여 둡니다.** 별도 `후렴` 섹션을 두지 않습니다.

원본 찬송가 DB 가 이미 그 형태였고, 가져올 때 절 간 공통 접미사를 후렴으로
떼어냈던 것을 되돌린 것입니다. 되돌린 이유는 두 가지입니다.

- 후렴 곡 586곡 중 **97곡은 절 끝 어절이 후렴을 수식**합니다. 새9 는
  `…성부와 성자와 성령 삼위의` + `하나님 우리 예배를 받아 주시옵소서` 로,
  한 문장이 두 섹션에 쪼개져 있었습니다
- 1·2·3·4절 뒤에 후렴이 한 번 오는 구조라 **화살표로 순서대로 진행할 수 없었습니다**

```bash
npm run chorus:merge
```

절을 먼저 채운 뒤 후렴 섹션을 지우므로, 중간에 실패해도 후렴이 사라지지 않습니다.
재가져오기(`npm run hymns:import`)도 이제 후렴을 떼지 않습니다 — 옛 동작이 필요하면
`-- --split-refrain` 을 붙이세요.

### 가사 줄나눔

원본 찬송가 DB 에는 줄바꿈이 없어, 가져올 때 글자 폭만 보고 나눴습니다. 그 결과
구 한가운데가 끊겼습니다 — 새256 의 `묵묵히 참고` | `당하셨네` 처럼.

**같은 곡의 절들은 같은 멜로디**라 행 구조가 서로 같아야 한다는 제약으로 다시
맞춥니다. 실제로 새256 은 `9.9.9.9`, 새305 는 `8.6.8.6`(Amazing Grace 의 Common
Meter)으로 세 절·네 절이 정확히 일치합니다.

행 수는 **짝수를 고릅니다.** 홀수 행은 어떤 배수로도 깔끔히 나뉘지 않아 2줄씩
표시에서 마지막 한 줄이 혼자 남습니다. 짝수를 강제하면 어절이 갈라진 행의 비율이
7.82% → 8.20% 로 조금 늘지만, 홀수 행 곡이 286곡 → 0곡이 됩니다
(`npm run measure:meter` 로 재현할 수 있는 측정입니다).

```bash
npm run lyrics:realign
```

기본은 **미리보기**입니다. 바꾸기 전에 전/후를 보고 리포트를 남깁니다.

```bash
npm run lyrics:realign -- --apply
```

안전장치:

- `lines_source` 가 `auto` 인 섹션만 건드립니다 — **사람이 손본 가사는 그대로**
- 신뢰도 `high` 만 자동 적용, 나머지는 리포트에만 남기고 손대지 않습니다
- 두 언어가 섞인 섹션은 건너뜁니다 (줄 짝이 깨집니다)
- 어절 경계에서만 끊으므로 **본문은 한 글자도 바뀌지 않습니다**

운율에 주기가 없는 곡(새8 `거룩 거룩 거룩` = `11.12.12.10`)은 이 방법으로 행 수를
정할 수 없어 자동 적용에서 빠집니다. 절이 하나뿐인 곡도 비교 대상이 없어 제외됩니다.

### 줄나눔 검토

자동 정렬은 **제안**입니다. **검토** 탭에서 곡마다 승인해야 확정됩니다.
승인한 곡은 `lines_source = manual` 이 되어 **이후 어떤 자동 작업도 건드리지 않습니다.**
찬양 탭의 곡 목록에도 초록색 **승인** 표가 붙어, 내 작업이 남아 있는지 눈으로 확인할
수 있습니다. 재정렬·후렴 병합 스크립트는 이 곡들을 건너뜁니다.

| 키 | 동작 |
|----|------|
| `Enter` | 승인 + 다음 곡 |
| `↑` `↓` (`k` `j`) | 이동 |
| `P` | 이 곡을 실제로 송출해 보기 |

1,000곡이 넘으므로 마우스로는 끝나지 않습니다. Enter만 눌러 진행하도록 만들었습니다.
행마다 글자 수를 나란히 보여 주는데, **절끼리 같은 숫자가 나오는지**가 판단 근거입니다.
24자를 넘는 행은 색으로 표시됩니다(현재 데이터에는 없습니다).

`P` 는 **실제 송출 화면을 바꿉니다.** 예배 중에는 쓰지 마세요 — 준비 시간에만 씁니다.

정렬 순서를 셋 중에 고릅니다.

| 순서 | 쓰임 |
|------|------|
| **손봐야 할 곡 순** (기본) | 절이 하나뿐이라 자동 정렬을 못 한 곡(56곡), 홀수 행이 남은 곡부터 |
| 자주 쓴 곡 순 | 시간이 없을 때 — 실제 쓰는 곡부터 |
| 곡집·번호 순 | 전체를 빠짐없이 훑을 때 |

목록의 노란 표를 보면 왜 손봐야 하는지 바로 알 수 있습니다. 표가 없는 곡은 절 간
정렬이 성공한 곡이라 대개 그냥 승인하면 됩니다.

줄을 고쳐야 하면 **수정하기**를 누르면 그 자리에서 편집창이 열립니다. 한 줄이 화면의
한 행이고, `[1절]` 로 절을 나누며 `|` 로 시작하면 윗줄의 다른 언어 가사가 됩니다.
저장하면 자동으로 확인 완료가 됩니다 — 사람이 직접 고친 것보다 확실한 확인은 없기
때문입니다.

편집 중에는 `Enter` 가 승인이 아니라 줄바꿈으로 동작합니다.

### 표시 행 폭 (템플릿)

가사는 **악보의 운율 행 단위로 저장**하고(새256 = `9.9.9.9`), 표시할 때 템플릿의
`한 행 최대 글자`(기본 24자)에 맞춰 인접 행을 **짝으로** 묶습니다.

| 템플릿 | 폭 | 새256 표시 |
|--------|---:|-----------|
| 찬양 — 이중 언어 / 단일 언어 | 24자 | `19자 2행` |
| 찬양 — 전체화면 큰 글씨 | 14자 | `9자 4행` |

세밀하게 저장하는 이유는 **되돌릴 수 없기 때문**입니다. 긴 행으로 저장하면 다시
쪼갤 안전한 방법이 없지만, 짧은 행은 언제든 묶을 수 있습니다.

반드시 짝으로 묶습니다 — 3행을 `2+1` 로 묶으면 행 길이가 들쭉날쭉해지고 홀수 행이
되어 2줄씩 표시에서 마지막 한 줄이 혼자 남습니다. 그래서 절반으로 나누어떨어지고
결과가 짝수일 때만 묶고, 모든 짝이 폭 안에 들어와야 실행합니다.

### 화면 나눔과 고아 줄

한 화면에 담을 줄 수(`1줄씩`·`2줄씩`·`4줄씩`)를 정하면 **고아 줄을 만들지 않게**
나눕니다. 3줄짜리 절을 `2+1` 로 잘라 마지막 한 줄만 다음 화면으로 넘기지 않습니다.

| 줄 수 | 설정 | 결과 |
|------:|------|------|
| 3 | 2줄씩 | 한 화면 (`2+1` 아님) |
| 5 | 2줄씩 | `3+2` (`2+2+1` 아님) |
| 6 | 4줄씩 | `3+3` (`4+2` 아님) |

찬송가 섹션의 30%(1,484/4,877)가 홀수 줄이라 실제로 자주 일어나던 문제입니다.
한 화면이 설정보다 한 줄 넘칠 수 있고, 그때는 출력 페이지가 배율로 줄여 담습니다.

### 곡집 추가

**곡집 관리** 버튼에서 만들고 가져옵니다. 가져오기는 **미리보기를 먼저** 보여줍니다 —
형식이 제각각인 자료를 잘못 해석해 조용히 넣는 것이 최악이기 때문입니다.

```
42. 주만 바라볼지라        ← 「번호. 제목」이 곡의 시작
[1절]
주만 바라볼지라
| Look to Jesus only      ← 직전 줄의 번역

118. 나의 등뒤에서
나의 등 뒤에서 나를 도우시는 주
```

번호가 없는 곡집은 구분선(`---`)으로 곡을 나누고 `제목:`·`저자:`·`저작권:`·`CCLI:` 로
정보를 넣습니다.

- **추가** / **교체**(기존 삭제)를 고를 수 있어 개별·일괄 갱신이 같은 방식으로 동작합니다
- 가져온 뒤 **빠진 번호**를 알려줍니다 (자료가 일부만 들어왔는지 확인용)
- 곡집을 지워도 수록곡은 사라지지 않고 `기타` 로 옮겨집니다

### 새찬송가 ↔ 통일찬송가

두 판본은 **별도 곡**으로 둡니다. 교차 매핑 428쌍 중 **91%가 가사가 다릅니다**
(새찬송가가 개정: "삼위일체 신께" → "성 삼위일체께"). 한 곡으로 합치면 본문이 사라집니다.

대신 **대응곡**으로 이어 두어, 새 305장을 열면 "대응곡: 통405"가 보이고 눌러서 넘어갈
수 있습니다. 나이 있는 성도가 통일 번호를 부를 때 쓰는 경로입니다.

`npm run hymns:import` 로 찬송가를 가져옵니다.

| 판본 | 곡 | 후렴 검출 (확실/유력/확인필요) |
|------|---:|---|
| 새찬송가 | 645 | 189 / 75 / 50 |
| 통일찬송가 | 557 | 169 / 67 / 38 |

**총 1,202곡**, 판본 간 번호 교차 매핑 428곡. 곡은 번호(`305`·`새 305`·`통일 405`)·
제목(공백 무시)·가사 부분일치로 찾습니다.

원본 찬송가 DB는 그대로 쓸 수 없어 세 가지를 자동 처리합니다. **모두 제안이며**
가져오기 리포트에 신뢰도별로 남으니 편집 UI에서 확인하세요.

1. **자동 줄나눔** — 원본에 줄바꿈이 전혀 없습니다(가사 한 줄 통짜, 평균 79자).
   어절 경계에서 균형 있게 나눕니다(결과: 평균 18자/줄, 40자 초과 0건).
2. **후렴 분리** — 후렴이 각 절 뒤에 인라인으로 반복되어 있습니다. 절 간 최장 공통
   어절 접미사를 후렴으로 보고 별도 섹션으로 뗍니다. 어절 수가 적으면 우연일 수
   있어 신뢰도를 함께 기록합니다.
3. **아멘 흡수** — '아멘'만 있는 절(새찬송가 298곡)은 별도 절로 만들지 않고 곡 속성으로 둡니다.

### 2언어 가사

원본에는 **한국어만** 있습니다. 영어(또는 다른 언어)는 찬양 탭 → 가사 편집에서
붙여넣습니다. `|` 로 시작하는 줄이 직전 줄의 번역으로 짝지어져 화면에서 위아래로 겹칩니다.

```
[1절]
나 같은 죄인 살리신
| Amazing grace how sweet the sound
주 은혜 놀라워
| That saved a wretch like me
```

가사를 통짜 텍스트로 저장하지 않고 **줄 단위 + `lineIndex` 페어링**으로 두는 이유가
여기 있습니다 — 통짜로는 "한국어 3번째 줄 ↔ 영어 3번째 줄"을 짝지을 방법이 없습니다.

> `npm run hymns:import` 를 다시 돌리면 `hymn_new`·`hymn_old` 출처의 곡을 지우고
> 다시 넣습니다. 직접 추가한 영어 가사도 함께 사라지므로 주의하세요.
> 사용자가 직접 등록한 곡(`manual`)은 건드리지 않습니다.
