### R-1. Origin 검사를 Host 위조로 뚫을 수 있다 (중간) — ✅ 조치됨 (`d4e8661`)

H-3 수정은 **Origin 을 Host 와 비교**합니다(`lib/origin-check.ts:59`). 그런데
**Host 도 접속하는 쪽이 정하는 값**입니다. 둘을 서로 맞춰 보내면 통과합니다.

격리 서버(7810) 실측:

| 시도 | 결과 |
|---|---|
| `Origin: https://evil.example` | 거부 (401) ✅ |
| `Origin` 없음 (OBS·도구) | 접속됨 ✅ (의도된 동작) |
| **`Origin: http://evil.test:7810` + `Host: evil.test:7810`** | **접속됨** ❌ |

**실제로 어떻게 악용되는가** (DNS 리바인딩): 공격자가 `evil.test` 를 **7777 포트로**
서비스하다가 DNS 를 `127.0.0.1` 로 바꿉니다. 오퍼레이터가 그 주소를 한 번 열면, 그
페이지가 우리 서버에 붙어 송출 화면을 바꿉니다.

**다만 좁습니다.** Origin 에 포트가 들어가야 Host 와 맞으므로, 공격 페이지 자체를
**7777 포트로** 띄워야 하고 오퍼레이터가 `evil.test:7777` 같은 주소를 열어야 합니다.
평범한 `http://evil.test`(80포트)로는 Origin 에 포트가 없어 **막힙니다.**

**고치는 법** — Host 도 우리가 실제로 서비스하는 주소인지 확인합니다. 열 줄이면 됩니다.

```ts
// lib/origin-check.ts — originHost === host 뒤에 한 겹 더
const LOCAL = new Set(['localhost', '127.0.0.1', '[::1]']);
// hostname 이 LOCAL 이거나 이 PC 의 LAN 주소일 때만 통과
```

> ⚠️ 이걸 고칠 때 **`location.host` 로 붙는 우리 페이지 3개**(컨트롤 패널·출력·강사
> 모니터)와 태블릿(`start:lan`, LAN IP 로 접속)이 끊기지 않아야 합니다. 태블릿 주소를
> 허용 목록에 넣어야 합니다.
