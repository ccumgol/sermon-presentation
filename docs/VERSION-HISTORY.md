# 판 이력 (Version History)

받는 사람이 **"내 것이 어느 판이고 무엇이 달라졌나"** 를 한 자리에서 보는 문서입니다.
자세한 판단 근거와 검증 방법은 [work-log](work-log.md) · [CHANGELOG](CHANGELOG.md) 에 있습니다.

---

## 판 번호를 붙이는 규칙 (2026-09-12, 사용자 결정)

**표준 semver** 를 그대로 씁니다 — `major.minor.patch`.

| 자리 | 무엇 | 보기 |
|---|---|---|
| **마지막** | 간단한 고침 | `1.0.3` → `1.0.4` |
| **가운데** | 기능이 늘거나 고침이 쌓였을 때 | `1.0.9` → `1.1.0` |
| **앞** | 크게 달라졌을 때 | `1.9.0` → `2.0.0` |

**커밋할 때마다 올립니다.** `package.json` 의 `version` 이 곧 판 번호이고,
설치 파일 이름(`SermonPresentation-1.0.4-arm64.dmg`)과 설정 탭의
**서버 정보 → 판** 에 **그대로** 나옵니다 — 저장한 값과 보이는 값이 같습니다.

> 가운데를 언제 올리나: **숫자 때문이 아니라 달라진 양 때문에** 올립니다.
> 고침이 대여섯 개쯤 쌓이거나 기능이 하나 늘면 올릴 때입니다. 기능이 없는데
> 숫자만 채우려고 올리면, 받는 사람이 '뭐가 달라졌나' 하고 찾게 됩니다.
>
> 마지막 자리에 상한은 없습니다 (`1.0.23` 도 정상입니다). 다만 열 가까이 쌓였다면
> 실제로 그만큼 달라진 것이니 가운데를 올릴 만합니다.

**Agent 에게**: 코드를 고쳐 커밋할 때 `package.json` 의 `version` 을 올리고 이 문서에
`## 1.0.5` 로 한 줄을 더합니다. 문서만 고친 커밋은 올리지 않습니다 — 프로그램이
그대로이기 때문입니다.

## 1.0.5 — 2026-09-12

**자료 꾸러미** — 성경·가사·악보를 다른 PC 로 한 번에 옮깁니다.

여태는 `bible.sqlite`(102MB)와 `sheets/`(48MB)를 **손으로 복사**해야 했습니다.
번들 파일 하나에 담기엔 너무 커서였습니다.

| | |
|---|---|
| 만드는 쪽 | `npm run data:pack` → `release/sermon-data-0.1.0/` (158MB) |
| 받는 쪽 | 데이터 폴더에 `install` 로 넣고 → 설정 탭 **자료 설치** |

- **누르기 전에 무엇이 되는지** 표로 보여 줍니다
- **이 PC 에서 손본 가사·순서표는 건드리지 않습니다** — 일부러 켜야 덮습니다
- 바꾸기 전에 지금 자료를 `backups/` 에 뜹니다. 백업이 실패하면 멈춥니다
- `VACUUM INTO` 로 떠서 **곡 0개짜리 꾸러미**가 나오지 않습니다
- 성경을 새로 넣었으면 **앱을 다시 시작**해야 반영됩니다

> 자료 꾸러미의 판(`0.1.0`)은 프로그램 판과 **따로** 매깁니다 — 가사를 고쳐도
> 프로그램은 그대로고, 프로그램을 고쳐도 자료는 그대로이기 때문입니다.

## 1.0.4 — 2026-09-12

**순서 표시의 담당자가 자리에 맞춰 나갑니다.** 담당자와 직분을 넣으면 자리가
넘치던 것을 고쳤습니다.

| 어떻게 치면 | 어떻게 나가나 |
|---|---|
| `성경봉독` ⏎ `김애리 전도사` ⏎ `MD연합여선교회 증경회장` | 담당자가 **두 줄**로 |
| `성경봉독` ⏎ `김애리 전도사 / MD연합여선교회 증경회장` | 한 줄 그대로, **넘치면 글자를 줄여서** |

**접을지 줄일지를 사람이 정합니다.** 전에는 여러 줄로 쳐도 한 줄로 합쳐 나갔습니다.

**순서 이름은 줄을 넘기지 않습니다.** 전에는 담당자가 길면 `성경봉독` 이
`성경 / 봉독` 으로 접혔습니다 — 화면의 기준점이 매번 다른 모양으로 접히면
눈이 먼저 그리로 갑니다. 자리가 모자라면 담당자 쪽이 줄어듭니다.

줄이는 한계는 **0.55 배**입니다. 그보다 작으면 회중이 못 읽습니다.
강사 모니터에도 같은 줄바꿈이 보입니다.

## 1.0.3 — 2026-09-12

**찬송가만 번호가 나옵니다.** 1.2.0 에서 모든 곡집의 번호를 뺐는데, 찬송가는
**회중이 손에 든 책을 펴야** 하므로 번호가 필요합니다.

| 곡 | 제목 화면 |
|---|---|
| 새찬송가 305장 | **새찬송가 305장** 나 같은 죄인 살리신 |
| 통일찬송가 405장 | **통일찬송가 405장** … |
| 많은물소리 265장 | 이 땅의 황무함을 보소서 |
| 시와찬미 · 찬미예수 | 제목만 |

가르는 기준은 **회중에게 책이 있는가**입니다. 경배와찬양 계열은 책이 없어 번호가
글자만 차지합니다.

> ⚠️ **이미 저장해 둔 순서표의 찬양에는 번호가 붙지 않습니다.** 어느 곡집이었는지를
> 항목에 적기 시작한 것이 이번 판이라, 그전에 넣은 항목은 알 방법이 없습니다.
> 찬송가에 번호를 띄우시려면 그 항목을 **지우고 다시 넣으세요**.
> (곡집 이름은 바꿀 수 있어서 이름으로 짐작하지 않습니다 — 바꾸는 순간 틀립니다)

한 곡이 새찬송가·통일찬송가 양쪽에 실려 있으면 **새찬송가 번호**를 씁니다.

## 1.0.2 — 2026-09-12

**찬양 제목 화면에서 곡집 이름과 장 번호를 뺐습니다.**

| | 전 | 후 |
|---|---|---|
| 화면 | 많은물소리 265장 이 땅의 황무함을 보소서 | **이 땅의 황무함을 보소서** |

회중에게 곡집 이름과 번호는 뜻이 없고, 제목 앞에 붙은 글자가 길수록 정작 제목이
작아집니다. 교독문·주기도문은 이미 같은 규칙이었고 **찬양만 예외**였습니다.

- 순서표 목록(조작 화면)에는 그대로 보입니다 — 조작자는 번호로 곡을 찾습니다
- 곡집·번호가 화면에 필요하면 슬라이드 안의 **저작권 줄**에 나옵니다
  (템플릿의 '저작권 표기')
- 제목이 비어 있는 곡만 곡집·번호를 대신 띄웁니다 (빈 화면보다 낫습니다)

## 1.0.1 — 2026-09-12

**송출 중인 찬양을 찬양 탭에서 곧바로 고칩니다.**

예배 순서에서 찬양을 띄운 뒤 오타를 발견하면, 전에는 찬양 탭에서 **같은 곡을
제목으로 다시 검색해** 들어가야 했습니다 — 가장 급한 순간에 가장 느린 길입니다.

이제 찬양 탭을 열면 슬라이드 목록 위에 **`✎ 이 곡 가사 수정`** 이 있습니다.
누르면 그 곡이 열리고 **가사 편집까지 펼쳐집니다.**

- 지금 **송출 중인 자리**의 곡을 엽니다 — 예배 순서 덱에 찬양이 여럿이어도
  엉뚱한 곡을 열지 않습니다
- **화면에 나가는 것은 바뀌지 않습니다.** 고쳐서 저장한 뒤 `곡 전체 송출` 을
  눌러야 반영됩니다 — 예배 중에 화면이 저절로 바뀌면 부르던 자리를 잃습니다
- 곡을 못 불러오면 편집 칸을 열지 않습니다 (빈 칸에 저장하면 가사가 날아갑니다)

> 안에서는 슬라이드가 **어느 곡인지**(`songId`)를 함께 싣고 다니게 했습니다.
> 제목만으로 찾던 옛 방식은 제목이 같은 곡이 둘일 때 갈라내지 못했습니다.

## 1.0.0 — 2026-09-12

**첫 정식 판.** 그전까지는 `0.1.0` 하나로 여러 번 다시 만들어서, 받는 사람이
어느 것을 쓰는지 **파일 이름으로는 알 수 없었습니다.**

이번 판에 들어간 것 (설치판 기준 2026-09-10 판 이후):

### 새 기능

- **카메라 영상 위에서 글자가 읽히게 하는 배경 레이어 둘**
  - *화면 전체* — 템플릿 탭 → 배경 → `단색·반투명 띠` + **투명도 슬라이더**.
    엔진은 전부터 있었지만 화면에 조절 칸이 없어 0.5 로 굳어 있었습니다
  - *글자 영역만* — 템플릿 탭 → 위치 → **`글자 영역 뒤에 네모 깔기`**.
    소제목·본문·참조를 **한 네모**가 감쌉니다 (글자 카드의 '글자 뒤 상자' 는
    줄마다 그려져 끝이 들쭉날쭉합니다)
- **항목 설정 칸의 높이를 끌어서 조절** — 예배 순서 탭에서 목록과 설정 칸 사이를
  끕니다. 슬라이더가 많은 항목('순서 표시' 등)의 아래쪽 설정이 잘려 보이던 것을 풉니다.
  더블클릭이나 `Home` 으로 기본값

### 고친 것

- **내 배경 폴더에서 고른 그림이 안 뜨던 것** — 템플릿이 *어느 폴더*에서 왔는지를
  담지 않아 늘 `data/backgrounds/` 에서 찾다가 404 가 났습니다.
  `~/Desktop/Data/Background` 의 그림은 **여태 한 번도 뜬 적이 없었습니다**
- **판이 섞여도 배경이 살아난다** — 폴더 정보 없이 온 그림이면 출력 화면이
  다른 폴더를 한 번 더 찾아봅니다. 옛 조작 화면·옛 설치판과 함께 써도 배경이 뜹니다
- **색상자로 색을 고르면 투명도가 사라지던 것** — 이제 색만 바뀌고 진하기는 남습니다
- **설정 탭 '이 PC 준비 상태' 가 윈도우에서 6초 걸리던 것** → 3초
  (설치 도구를 하나씩 찾다가 함께 찾도록)

### 설치 편의

- **맥 DMG 에 두 파일이 함께 들어갑니다** — `맥에서 처음 열기.command`(격리 표시를
  지우고 앱을 엽니다) · `먼저 읽어보세요.txt`(붙여넣을 수 있는 안내)
- **윈도우 설치 중에 OBS·Chrome 을 함께 설치**할 수 있습니다 (winget).
  실패해도 앱 설치는 그대로 끝나고, 앱의 '이 PC 준비 상태' 에서 다시 할 수 있습니다

### 아래에서 도는 것

- 밀 때마다 **CI 가 검사**합니다 (`tsc` · `vitest` · 빌드, Node 24·26 둘 다)
- 죽은 코드를 막는 설정 (`noUnusedLocals` · `noUnusedParameters`)
- 검사 **2,074개**
