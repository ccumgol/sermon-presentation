## 2026-08-21 (오후) — 새찬송가 영어 원제 641곡

**요청**: 노션에 모아 둔 한/영 찬송가 제목 표를 점검하고, 쓸 만하면 넣을 것.

### 왜 필요했나

`songs` 표에 `title_alt`(원제)·`author`·`composer` 열이 있는데 **4,396곡 전부 비어
있었다.** 그래서 '새찬송가 305장이 어느 영어 찬송인가' 를 알 방법이 없었다. 영어 가사를
찾으려면 그것이 먼저다.

### 출처를 먼저 점검했다

| 확인 | 결과 |
|---|---|
| 규모 | 새찬송가 1~645장 전곡 · **영어 제목 645/645** |
| 한국어 제목 (우리 DB 대조) | 625/645 일치 |
| 통일찬송가 번호 | 481건 · **558 초과(불가능한 번호) 0건** |
| 영어 제목 | 634종 · 중복 7종은 대부분 정당(`Amen` 6회) |
| 실제 송출 29곡 | **23곡 커버** |

`HymnData.plist` 와도 맞대 봤다 — 통일 번호 477건 중 471 일치. 불일치한 새 606장은

사용자 결정: '우리 제목을 사용해줘'. 그런데 **'제목으로 짝짓기' 를 일괄 적용하면 안 된다** —

```
번호   우리 제목          출처 한국어          출처 영어
```

그래서 자동 규칙이 아니라 **사람이 판정한 표**(`RESOLVED_SUSPECTS`)를 코드에 두고,
줄마다 **근거**를 적었다.

| 새 | 우리 제목 | 넣은 원제 | 근거 |
|---|---|---|---|
| 631 | 우리 기도를 | Hear Our Prayer, O Lord | 「우리 기도를」의 정석 영어 응답 |
| 632 | 주여 주여 우리를 | O Lord, O Lord! | '주여 주여' ↔ 'O Lord, O Lord' 대응 |
| 638 | 주 너를 지키시고 | The Lord Bless You and Keep You | 민수기 6:24 축도와 일치 |
| 639 | 주 함께 하소서 | **(비움)** | 출처에 이 곡이 없다 — 짐작해 채우지 않는다 |

```
넣었습니다: 원제 3곡 · 연결 0건
확인: 어긋난 구간 — 판정한 3곡은 채워지고, 나머지는 비어 있습니다
```

**원제가 채워진 곡: 644 / 645.** 남은 하나(새 639)는 출처에 없어서 비워 뒀다.
스크립트의 자기 검증이 '판정한 것은 채워졌고 나머지는 비어 있다' 를 확인한다 —
경계를 코드가 지킨다. 테스트 931개 통과.

> 하는 것은 별도 작업이다.

## 2026-08-20 (밤, 후속 2) — 저장해도 인용구가 남는다 · 프로젝터 순서 표시 글자 통일

**사용자 지적 두 가지.**

### ① 저장하면 인용구가 성경 항목으로 되돌아갔다 (버그)

> 인용구로 추가한 후에 '템플릿 업데이트' 를 클릭하면 인용구들이 모두 '성경' 처럼
> 타이틀과 본문으로 바뀐다. 매주 미리 준비한 후에 '템플릿 업데이트' 로 저장을
> 대신해서 쓸 것 같은데, 인용구가 바뀌어 버리면 인용구로 쓴 의미가 없어진다.

원인은 저장 경로의 **화이트리스트**다. `normalizeItems` 는 아는 필드만 하나씩 옮겨
담고 나머지는 버린다 — 모르는 쓰레기가 순서표에 박히지 않게 하는 옳은 설계다. 그런데
인용구를 만들면서 거기에 `quote`·`preview` 를 **더하지 않았다.** 화면에서는 잘 보였으므로
저장하기 전까지 알 수 없었다.

고친 것: 그 두 필드를 화이트리스트에 넣었다.

| 규칙 | 왜 |
|---|---|
| `quote` 는 **`true` 만** 받는다 | `'yes'` 같은 값이 박히면 판정이 흐려진다 |
| `preview` 는 **인용구일 때만** 담는다 | 본문 낭독에는 쓰이지 않는다 — 뜻 없는 값을 남기지 않는다 |
| `preview` 는 길이를 잘라 담는다 | 라벨이다 (`PREVIEW_MAX`) |

**같은 부류의 버그를 막는 테스트를 만들었다** — `tests/integration/plan-item-roundtrip.test.ts`.
종류마다 **모든 선택 필드를 채운 항목**을 저장 경로에 통과시켜 하나도 빠지지 않았는지
본다. 새 필드를 넣고 그곳을 잊으면 실패한다. 나머지 다섯 종류(성경·찬양·교독문·순서
표시·전례문)를 대조했고 빠진 것은 없었다.

### ② 프로젝터의 순서 표시 글자 크기를 고르게

> 프로젝터 화면의 '예배 순서' 표시는 글자 크기를 리듬있게 하지 말고 첫 글자의 크기로
> 동일하게 해줘.

대비가 낮은 프로젝터에서는 작아진 글자가 먼저 뭉개진다. 두 곳을 막았다.

| 무엇 | 어디서 |
|---|---|
| 자동 리듬 | `projectorTemplate()` 이 `titleRhythm: 0`, `titleRhythmY: 0` 을 **명시한다** |
| **손으로 맞춘 글자별 조정** | `projector.css` 가 `.rhythm-char` 의 인라인 크기를 되돌린다 |

자동 리듬은 '전체' 프리셋에 설정이 없어 이미 0 이었다(`clampRhythm(undefined)`).
그래도 명시한 이유: 나중에 그 템플릿에 리듬을 넣어도 프로젝터는 고르게 남는다.

진짜 원인은 **수동 조정**이었다 — 사용자 순서표의 `찬양과경배` 에 글자별 크기가
`0.8`·`0.9` 로 박혀 있었다. 그것은 항목에 담겨 있고 렌더러가 **인라인**으로 꽂으므로
템플릿으로 막을 수 없다. CSS 로 덮었다. 인라인을 이기려면 `!important` 뿐이고,
**렌더러가 만든 표시용 인라인을 표시 전용 화면에서 되돌리는** 이 자리가 그것이 옳은
경우다 (색·크기처럼 CSS 변수로 되는 것은 `body` 선언으로 처리했다 — 이것만 예외다).

`1em` 은 부모 글자 크기 = **첫 글자의 크기**다 (리듬 표의 첫 칸이 `1.0`).

## 2026-08-20 (밤, 후속) — 인용구가 네 화면에서 같은 글로 나온다

**사용자 지적**: 인용구를 실행하면 네 화면의 말씀 형식이 모두 다르다.

```
관리자      고전 1:3 하나님 우리 아버지와…
OBS         고전 1:3 ⏎ 3 하나님 우리 아버지와…
강사 모니터   3 하나님 우리 아버지와… ⏎ 고전 1:3
프로젝터     하나님 우리 아버지와…
```

### 왜 넷이 달랐나

네 화면이 **서로 다른 렌더러**를 쓰고 참조·절 번호 규칙이 제각각이었다.

| 화면 | 규칙 |
|---|---|
| 관리자 목록 | `describeItem` 이 참조 뒤에 미리보기를 붙인다 |
| OBS | 참조를 **별도 줄**(`#reference`)로 위/아래에 그리고 절 번호를 붙인다 |
| 강사 모니터 | 절 번호를 **늘** 붙이고(설정을 보지 않았다) 참조를 아래에 붙인다 |
| 프로젝터 | '전체' 템플릿이 참조·절 번호를 **둘 다 끈다** |

`showReference: 'inline'` 이라는 값은 타입에 있었지만 **구현이 없었다** — `'none'` 이
아니면 무조건 별도 줄이었다.

### 참조를 **본문 글자에 넣었다**

참조를 별개 요소로 두는 한 렌더러 셋을 각각 고쳐야 하고, 프로젝터는 템플릿이 참조를
끄므로 예외가 또 필요하다. **규칙이 넷이면 넷은 다시 어긋난다.**

글자로 넣으면 네 화면이 그것을 '본문' 으로 받으므로 어긋날 자리가 **구조적으로**
없어진다. 접두사는 **항목의 `ref`** 를 쓴다 — 목록 줄과 글자까지 같아진다
(서버가 주는 `slide.reference` 는 정식 이름 `고린도전서 1:3` 이라 목록과 달라진다).

DB 는 손대지 않는다. 화면에 보낼 **사본**을 만든다 (`quoteSlides` 는 불변이다).

### 함께 끈 것

| 무엇 | 왜 |
|---|---|
| 절 번호 | `고전 1:3` 에 이미 절이 있다 — 안 끄면 `고전 1:3 3 하나님…` |
| 별도 참조 줄 | 붙였는데 아래에도 나오면 같은 것이 두 번 나간다 |
| 보조 역본 접두사 | 붙이지 **않는다** — 참조가 두 번 보인다 |

항목의 **참조 표기를 `끔`** 으로 두면 접두사를 붙이지 않는다 — 그 토글이 인용구에서도
뜻을 갖는다.

### 강사 모니터가 설정을 따르게 했다

`stage.js` 가 절 번호를 **늘** 붙이고 있었다(`verse.verse + ' ' + verse.text`).
`display.verseNumbers === false` 를 보게 했다. 이 파일은 의존성 0 이라 규칙을 두 곳에
적게 되므로 `tests/unit/quote-consistency.test.ts` 가 **파일을 읽어** 묶어 둔다.

### 📖 성경(본문 낭독)은 조금도 바뀌지 않았다

`resolveItem` 이 `item.quote` 일 때만 이 변환을 부른다. 실측으로 확인했다 —
`창 1:1-6` 은 절 번호 `1`, 참조 줄 `창 1:1-6`, 보조 역본까지 예전 그대로다.

### 실측 (네 화면 동시)

| 화면 | 나온 글 |
|---|---|
| 관리자 목록 | `고전 1:3 하나님 우리 아버지와 주 예수 그리스도로부터 은혜와 평강이 있기를 원하노라` |
| OBS(미리보기) | 같음 · 참조 줄 없음 · 절 번호 없음 |
| 강사 모니터 | 같음 (한 줄) |

| 성경 낭독 대조 | `1태초에 하나님이…` + `1In the beginning…` · 참조 줄 `창 1:1-6` — **그대로** |

## 2026-08-20 (밤) — 인용구를 '성경 절 낱개'로 바꿨다

**요청**: 광고와 인용구가 기능이 겹친다. 인용구는 성경 본문을 **카테고리가 아닌 개별
슬라이드로** 가져오는 기능으로 바꾼다. 성경에서 `창 1:1-6` 은 '창 1:1-6' 타이틀 밑에
6절이 들리지만, 인용구에서는 **타이틀 없이** 창 1:1 … 창 1:6 이 나온다.

### 겹쳐 있던 것이 맞았다

광고와 인용구는 화면에서 **똑같이 그려졌다**(둘 다 `kind: 'text'`). 실제 차이는
아이콘과 `↩ 직전으로` 뿐이었다. 그리고 사용자가 갖고 있던 인용구 항목의 내용이
바로 **`창 3:15`** 였다 — 이미 참조를 인용구로 쓰려 했고, 지금은 글자 그대로 화면에
나갔다. 요청과 정확히 맞는 증거였다.

### 무엇이 바뀌었나

| | 📖 성경 | 💬 인용구 |
|---|---|---|
| `창 1:1-6` | 항목 **하나** | 항목 **여섯** (`창 1:1` … `창 1:6`) |
| 목록 줄 | 머리 줄 + 펼치면 6장 | 여섯 줄, 각 줄에 **본문 함께** |
| 펼치기 | `▸` 로 장을 고른다 | 없다 — **한 번 클릭으로 송출** |
| 제목 슬라이드 | 참조가 먼저 나간다 | **나가지 않는다** |
| `↩ 직전으로` | 없음 | 있음 (유지) |

### 성경 항목과 **같은 구조**로 담았다

인용구도 `type: 'bible'` 이고 `quote: true` 표시만 다르다. 자유 글자로 담으면 역본을
바꿀 수 없고 본문이 순서표에 복사된다. 같은 구조로 두면 역본·참조 표기·절 번호·글꼴·
템플릿이 **그대로** 쓰이고, **본문은 언제나 DB 가 원본**이다.

### 목록 줄의 본문은 항목이 담는다

`창 1:1 태초에 하나님이 천지를 창조하시니라` 처럼 보여 달라는 요청이었다. 그런데
컨트롤 패널은 **펼친 항목 하나만** 본문을 조회한다(`resolveItem`) — 낱개로 흩어진
여섯 줄의 본문을 조회 없이 그릴 방법이 없다. 그래서 `preview` 를 항목에 담는다
(`songTitle`·`readingTitle` 과 같은 이유).

**라벨일 뿐이다.** 화면에 나가는 본문은 언제나 DB 에서 다시 읽으므로 잘려 있어도 되고
없어도 된다(없으면 참조만 보인다). 역본을 바꾸면 새 역본으로 다시 읽는다.

### 막은 버그 두 개

- **비동기 뒤의 덮어쓰기**: 역본을 바꾼 직후 미리보기를 다시 읽는 경로가 옛 `items`
  배열로 덮어써 **역본 변경을 되돌렸다.** `patchItems` 가 함수형 갱신을 받게 하고
  그 경로를 함수형으로 바꿨다. 항목을 여러 개 넣는 `insertItems` 도 같게 했다 —
  자리는 어긋나도 되지만 항목이 사라지면 안 된다.
- **한 번에 여러 개**: `insertItem` 을 여섯 번 부르면 `items` 가 이 렌더의 값이라
  마지막 하나만 남는다. `insertItems` 로 한 번에 넣는다.

### 옛 항목

옛 자유 글자 인용구는 **그대로 나간다**(광고처럼 글자가 뜬다). 새로 만들 수만 없다.
사용자의 한 건(`창 3:15`)은 요청에 따라 지웠다 — `scripts/remove-text-quotes.ts`
(미리보기 기본 · 무엇을 지울지 내용까지 보여 준다 · `--apply` 가 스냅샷을 먼저 뜬다).

### 실측

| 확인 | 결과 |
|---|---|
| `창 1:1-6` 넣기 | 6줄 · `인용구 6개를 넣었습니다 — 창 1:1-6` |
| 목록 줄 | `창 1:1 태초에 하나님이 천지를 창조하시니라` (요청한 모양) |
| 펼치기 | 인용구 줄에 `▸` 없음 · 성경 줄에는 있음 |
| 한 번 클릭 | 제목 없이 `4빛이 하나님이 보시기에 좋았더라…` 가 바로 나갔다 |
| `↩ 직전으로` | `(순서 표시)` 로 뜨고, 누르면 설교 화면으로 돌아왔다 |
| 역본 바꾸기 | 목록 줄이 `창 1:2 Now the earth was formless…` 로 다시 읽혔다 |
| 실제 데이터 | 옛 인용구 1개 삭제 · 주일예배 22 → 21개 · 순서 표시 8개 그대로 |
| 테스트 | 877개 통과 (`verse-quotes` 17개 추가) |

## 2026-08-20 (저녁) — 프로젝터: 주소줄을 실제로 없애기

**사용자 재요청**: 스크린샷으로 제목줄('프로젝터 — Sermon Presentation')과
출처줄('127.0.0.1:7777/projector/')을 빨간 박스로 표시하며 "없앨 수 없나".

### 기능은 있었지만 **찾을 수 없었다**

전체 화면(`F`)이 이미 있었는데 도달하지 못했다. 원인은 둘로 본다 — `F` 를 눌러야 하는
것을 몰랐거나, **키보드 초점이 브라우저 쪽에 있어서** `F` 가 페이지에 닿지 않았다.
창을 열고 바로 누르면 실제로 그렇게 된다. 둘 다 **클릭**으로 풀린다.

| 무엇 | 왜 |
|---|---|
| **화면을 클릭하면 전체 화면** | 가장 찾기 쉬운 동작. 클릭은 초점도 함께 가져온다 |
| 클릭으로 **나가지는 않는다** | 예배 중 실수로 벽에 브라우저 창이 드러나면 안 된다 |
| 막대를 누른 클릭은 제외 | `+` 를 누르려다 전체 화면이 되면 안 된다 |
| **전체 화면 선택을 기억한다** | 다음에 열면 첫 클릭·키 입력에서 저절로 들어간다 |
| 마우스 이동은 세지 않는다 | 브라우저가 사용자 동작으로 인정하지 않아 거절되고, 기회를 잃는다 |
| 사람이 직접 나가면 기억을 끈다 | 창 모드로 쓰겠다는 뜻이다 |
| 안내는 전체 화면이 아닐 때만, 막대와 함께 | 상시 표시하면 프로젝터 번인 위험 |

### '앱으로 설치' 를 붙였다 (PWA)

매주 쓰는 화면이라면 설치판이 `F` 보다 편하다 — **애초에 주소줄이 없는 창**으로 열리고,
`display: fullscreen` 이라 처음부터 전체 화면으로 뜬다. 클릭조차 필요 없다.

아이콘 PNG(192·512)는 **코드로 그린다** — `scripts/make-projector-icons.ts` 가
`node:zlib` 만으로 만든다. 이미지 도구를 깔지 않아도 되고, 무엇을 그렸는지 읽어서 알 수
있다(바이너리는 diff 가 되지 않는다). 검은 바탕에 흰 가로 막대 셋 — 벽에 비친 글줄.

설정 탭에 **프로젝터로 띄우기** 카드를 넣었다. 방법을 **찾을 수 있는 자리**가 필요했다.

### 실측

| 확인 | 결과 |
|---|---|
| 매니페스트 | `200 · application/manifest+json` · `display: fullscreen` · 아이콘 2개 |
| 아이콘 | 530 B / 1,939 B · PNG 서명 확인 |
| **실제 클릭 · 실제 `F`** | 둘 다 `requestFullscreen` 호출 · 기억 `1` 저장 |
| 막대 클릭 | 기억을 바꾸지 않는다 |
| 거절돼도 화면 정상 | 본문 그대로 · `diag.errors = 0` |
| 테스트 | 860개 통과 (`projector-page` 7개 추가) |

> ⚠️ **전체 화면이 실제로 켜지는 것은 확인하지 못했다.** 검증에 쓰는 임베드 브라우저 창이
> Fullscreen API 자체를 막는다(`Permissions check failed`). **호출까지** 확인했고,
> 브라우저가 허용하는지는 표준 동작에 맡겼다.

## 2026-08-20 (오후) — 프로젝터 화면 (`/projector`)

**요청**: 가끔 프로젝터로 띄워야 한다. TV 가 아니라 프로젝터면 선명하지 않아 글자를
크고 두껍게 해야 한다. 강사 모니터처럼 별도 창으로, '전체 — 성경·찬송 겸용' 처럼 표시.
주소줄·시계·제목·다음 화면·연결됨·글자 크기 라벨은 전부 없애고 풀스크린.
마우스를 올릴 때만 막대가 보이고 그 안에서 `+ −` 로 글자 크기. 색 반전 옵션.

### OBS 와 **동시에 다른 배치**를 쓴다

이것이 핵심이다. 카메라 영상 위에는 '하단 두 줄'로 나가면서, 같은 내용이 프로젝터에는
큰 글씨로 나간다. 템플릿을 갈아 끼울 필요가 없다.

| 화면 | 템플릿 |
|---|---|
| OBS 송출 | 활성 템플릿 (예: 하단 두 줄) |
| 프로젝터 | **'전체 — 성경·찬송 겸용'** 고정 |

`server/ws.ts` 의 `templateFor()` 가 `projector` layer 에만 다른 템플릿을 보낸다.
`getTemplateOrDefault(-8)` 를 거치므로 **'전체' 프리셋을 고치면 프로젝터도 따라간다** —
눈에 보이지 않는 별도 설정을 만들지 않았다. 다른 템플릿을 편집하는 중에 뿌리는
`style:set` 은 프로젝터에 보내지 않는다 (벽에 비친 글이 춤추면 안 된다).

### 렌더러를 복제하지 않았다

`output.js` 는 1044줄이고 성경·찬양·교독문·전례문 렌더러가 모두 들어 있다. 프로젝터
페이지는 **같은 DOM id** 를 두고 같은 CSS·같은 스크립트를 불러온다. `projector.css`/
`projector.js` 는 덧칠만 한다. `tests/unit/projector-page.test.ts` 가 파일을 읽어
이 규칙을 지킨다.

`output.js` 는 `location.pathname` 이 `/projector` 로 시작하면 layer 를 스스로 정한다 —
쿼리에 맡기면 즐겨찾기에서 빠졌을 때 OBS 화면으로 집계된다.

### 서버 패치와 싸우지 않는다

서버의 `style:patch` 는 CSS 변수를 `<html>` 인라인에 꽂는다. 그런데 **CSS 변수는
상속으로 결정된다** — 값을 읽는 쪽에서 가장 가까운 조상이 이긴다. `body` 가 `html` 보다
가까우므로 `body.projector { --primary-color: … }` 가 서버 패치를 가린다.
`!important` 도, 인라인을 지우는 짓도 필요 없다.

### autoFit 을 껐다

키우면 넘치고, 넘치니 되돌려 깎아서 **글자 크기가 안 바뀌는 것처럼 보인다** —
2026-08-19 에 내가 오진한 현상이 정확히 이것이다. 조작자는 벽을 직접 보고 있으니
넘치면 `−` 를 누르면 된다. 대신 넘치는 동안 막대에 알린다.

### 둘째 줄의 바닥을 받쳤다

'전체' 템플릿의 둘째 줄은 42px 이다(첫 줄의 0.44배). OBS 에서 *둘째 역본*을 곁들일 때를

웹페이지가 브라우저 주소줄을 없애는 방법은 없다(피싱 방지). **전체 화면**이 유일한

## 2026-08-20 — 교독문이 두 벌이 되었다 (통일찬송가용 / 새찬송가용)

**요청**: 지금 들어 있는 교독문은 통일찬송가의 것이다. 새찬송가 교독문 DB(`~/Desktop/Data/Kyodoc.sqlite`)
를 넣고, 교독문을 고를 때 '통일찬송가용' / '새찬송가용' 으로 구분해서 가져오게 해 달라.

### 왜 두 벌인가

찬송가마다 교독문이 다르고 **번호가 같아도 다른 글**이다 — 15번이 통일에서는 시편 51편,
새찬송가에서는 시편 27편이다. 덮어쓰면 예전 순서표의 교독문이 조용히 다른 글로 바뀐다.

### 무엇이 바뀌었나

| 곳 | 내용 |
|---|---|
| `responsive_readings` 표 | 기본 키가 `number` → **`(book, number)`**. 기존 76편은 `book='hymn_old'` 로 옮겼다 (자동, 여러 번 해도 같다) |
| `lib/kyodoc-parser.ts` (새 파일) | `NEW_KYODOC` 표 어댑터. `NAME`='1. 시편 1편', `DESCRIPTION`= 줄마다 `/` 로 끝난다. 통일찬송가 원본(txt)과 형식이 전혀 달라 어댑터를 따로 뒀다 |
| `scripts/import-kyodoc.ts` (새 파일) | 미리보기가 기본, `--apply` 로 넣는다. 원본은 **읽기 전용**으로 연다. 넣기 전에 스냅샷을 뜨고, **통일찬송가 76편이 그대로인지 스스로 확인**한다 |
| 예배 순서 탭 | 교독문 추가 칸 위에 **두 버튼**(편수 표시). 목록에서 새찬송가용은 `새 교독문 15. 시편 27편` |
| 항목 상세 | `새찬송가용 · 15번` 을 **보여만 준다.** 바꾸면 내용이 통째로 달라지므로 일부러 못 바꾸게 했다 |
| 화면 | 제목 슬라이드는 여전히 `교독문 15, 시편 27편` — **어느 찬송가인지 나가지 않는다.** 회중에게는 뜻이 없다 |

### 예전 순서표는 그대로 열린다

항목의 `readingBook` 이 **없으면 통일찬송가용**으로 본다. 새찬송가용을 넣은 항목에만
값이 붙으므로, 이미 만들어 둔 6개 순서표는 손대지 않아도 예전과 같은 글이 나온다.

### 넣은 결과

```
원본 행 137개 → 읽은 교독문 137편
번호 1~137 · 빠진 번호 없음
본문 줄 1542개 → 화면 795장
넣었습니다: 137편 (새찬송가용 0 → 137)
확인: 137편 · 줄 1542개를 다시 읽었습니다
확인: 통일찬송가용 76편은 그대로입니다
```

원본에서 발견한 문제 1건(**5번 '시편 8편'이 내용을 반복한다**)은 **고치지 않고 알렸다** —
[KNOWN-DATA-ISSUES §4.6](KNOWN-DATA-ISSUES.md) 참고.

### 확인

- 테스트 836개 통과 (`kyodoc-parser` 13개 새로 추가)
- 실제 화면: 두 버튼이 4번부터 갈리는 목록을 정확히 갈아 끼우고(통일 `시편 8편` / 새 `시편 5편`),

- 실제 DB: 순서표 6·템플릿 1·설정 1 그대로. 다시 반입해도 결과가 같다

## 이 프로젝트가 일하는 방식 (짧게)

- **추측 말고 실측.** 판단은 측정에서 나온다 — ESV 판본 비교, 운율 순위 규칙,
  폰트 대체 비율, 스크롤바 폭, 글자 크기 배수까지 브라우저에서 재고 정했다.
- **화면을 스스로 비우지 않는다.** 서버가 죽어도 출력은 마지막 내용을 유지한다.
- **자동 결과는 제안이다.** 사람이 승인해야 확정되고, 승인한 것은 자동이 건드리지 않는다.
- **되돌릴 수 없는 일 앞에는 백업과 미리보기.**
- 검증 3종은 항상 통과: `npx tsc --noEmit && npx vitest run && npx vite build`
  (2026-08-16 기준 **556개 통과**)
