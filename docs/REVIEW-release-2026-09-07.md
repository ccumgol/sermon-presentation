### 🟢 S-1 내보낸 번들에 접속 암호와 세션 열쇠가 들어 있다 — **고쳤다**

**증상.** 설정 탭의 '내보내기' 로 만드는 번들(JSON 한 파일)에 `lan_password`(scrypt
해시)와 **`lan_session_secret`(HMAC 서명 열쇠)** 이 그대로 실립니다. 이 파일은
**다른 PC 에 자료를 옮기려고 사람 손으로 나르는 파일**입니다.

**실측** (격리 서버):

```
settings 키: ['lan_password', 'lan_session_secret']
  lan_password       = scrypt$<소금 32자>$<해시 128자>
  lan_session_secret = <64자 hex>
```

열쇠만으로 쿠키를 만들어 서버에 물어봤습니다:

> 실제 값은 적지 않습니다. 이것은 격리 서버(별도 데이터 폴더 · 확인 뒤 지웠음)의
> 것이지만, **해시와 열쇠를 문서에 남기지 않는다**는 규칙(CLAUDE.md)을 여기서도
> 지킵니다 — 읽는 사람이 진짜인지 아닌지 구별할 수 없기 때문입니다.

```
  위조한 쿠키    : <만료시각>.<열쇠로 만든 서명>
  서버가 받아 주나: 예 — 암호 없이 통과한다
```

**왜 심각한가.** 세션 쿠키는 `<만료시각>.<서명>` 이고 서버는 열쇠만 압니다(설계 의도).
그 열쇠가 새어 나가면 **암호를 몰라도 누구나 유효한 쿠키를 만들 수 있습니다** —
LAN 접속 암호가 통째로 무력해집니다. 게다가 가져오기 쪽도 이 키를 덮어쓰므로,
번들을 받은 PC 는 **자기 암호가 남의 암호로 바뀝니다**(그리고 붙어 있던 태블릿이
전부 로그아웃됩니다). 이유를 알 수 없는 증상으로 나타납니다.

`data/app.sqlite` 를 읽기 전용으로 확인한 결과 **지금 이 PC 의 설정에도 두 키가
들어 있습니다** — 다음에 내보내기를 누르면 실제로 새어 나갑니다.

**조치(한 줄).** `server/routes/backup.ts` 의 제외 목록에 두 키를 넣습니다.
내보내기와 가져오기가 같은 집합을 쓰므로 한 곳만 고치면 양쪽이 막힙니다.

```ts
const EXCLUDED_SETTINGS = new Set(['live_state', 'lan_password', 'lan_session_secret']);
```

이미 남에게 준 번들이 있으면 `npm run password` 로 암호를 다시 정합니다 —
열쇠가 새로 발급되어 옛 번들의 열쇠가 죽습니다.

### 🟢 S-2 HTTP 라우트에는 Origin·Host 검사가 없다 — **고쳤다**

**증상.** 2026-08-22 의 R-1 은 **WebSocket** 에 `isServedHost` 를 붙여 DNS 리바인딩을
막았습니다. 그런데 **HTTP 라우트에는 그 검사가 아예 없습니다.** 검사는
`server/ws.ts` 한 곳에서만 부릅니다.

`lib/origin-check.ts` 머리말은 "REST 는 JSON 본문이라 프리플라이트가 걸려 상대적으로
안전하다" 고 적어 두었는데, **두 경우에 그 전제가 깨집니다.**

**실측 ①  본문이 필요 없는 POST 는 프리플라이트가 걸리지 않는다**

바깥 웹페이지 흉내 — `Origin` 은 남의 사이트, `Content-Type: text/plain`
(브라우저가 프리플라이트 없이 보내는 요청):

```
POST /api/songs/1/confirm   Origin: https://evil.example
  → HTTP 200  {"success":true,"data":{"id":1,"confirmed":true}}

DB 확인:  전 1|auto   →   후 1|manual
```

**`lines_source` 가 `auto` → `manual` 로 바뀌었습니다.** CLAUDE.md 가 "사람이 승인
버튼을 누른 표시이므로 Agent 도 손대지 않는다" 고 못 박은 그 값입니다. 곡 id 를
1부터 훑으면 4,531곡을 전부 '승인' 으로 만들 수 있고, 그러면 검토 대기열이 사라져
어디까지 봤는지 알 수 없게 됩니다. `POST /api/songs/:id/favorite` 도 같은 방식으로
통과했습니다(실측 200).

**실측 ②  Host 를 위조하면 읽기·쓰기가 다 열린다 (DNS 리바인딩)**

| 요청 | `Host: evil.example` 로 보냈을 때 |
|---|---|
| `GET /api/backup/export` | **HTTP 200** · 본문 5,210 bytes (실데이터라면 4,531곡 + S-1 의 열쇠) |
| `GET /api/songs` | **HTTP 200** |
| `WS /ws` | 거부됨 — 401 (R-1 이 여기서는 동작한다) |

리바인딩된 페이지는 **같은 출처**가 되므로 `application/json` 본문도 프리플라이트
없이 보냅니다. 그래서 파괴적인 경로까지 열립니다:

```
POST /api/backup/import   Host: evil.example   {"mode":"replace", …}
  → HTTP 200 · 곡 1 → 0
     (H-2 의 스냅샷은 정상적으로 떴다 — 되돌릴 수는 있다)
```

**조치.** `server/app.ts` 의 `onRequest` 훅에 한 겹을 더합니다. **WS 와 똑같은
규칙**이라 새 개념이 없습니다:

- `Origin` 이 있는데 `isAllowedOrigin(origin, host, allowed)` 가 아니면 거부
- `Host` 가 `isServedHost` 가 아니면 거부 (리바인딩 차단)

`Origin` 이 없는 요청(OBS·`curl`·테스트)은 지금처럼 통과합니다 —
**루프백 면제는 건드리지 않습니다.** 통합 테스트는 `lan-password.test.ts` 의
형식을 그대로 쓸 수 있습니다.

> ⚠️ 이 훅을 고칠 때 **OBS 브라우저 소스·프로젝터·강사 모니터가 계속 붙는지**를
> 반드시 다시 확인해야 합니다. 여기가 깨지면 예배 중 화면이 멈춥니다.

### 🟢 S-3 `style:set` 이 임의 CSS 속성을 출력 화면에 그대로 넘긴다 — **고쳤다**

**실측.** 출력 페이지 흉내 하나를 붙여 두고 `style:set` 을 보냈습니다:

```
보낸 것 : { "opacity": "0", "display": "none" }
받은 것 : {"opacity":"0","display":"none"}      ← 걸러지지 않았다
```

`public/output/output.js` 의 `applyStylePatch` 는 이 값을
`root.style.setProperty(키, 값)` 으로 넣습니다. 즉 `<html>` 에 `display:none` 이
붙어 **송출 화면이 통째로 사라집니다.** 이 프로젝트가 최악으로 꼽는 상태입니다.

게다가 **템플릿을 다시 보내도 복구되지 않습니다** — 템플릿은 `--` 로 시작하는 변수만
덮으므로 `display` 는 그대로 남습니다. OBS 소스를 새로고침해야 돌아옵니다.

도달 경로는 좁습니다(WS 에 붙을 수 있어야 하고, 그러려면 루프백이거나 쿠키가 필요).
하지만 **막는 비용이 세 줄**이고 피해가 예배 정지입니다.

**조치.** `server/ws.ts` 의 `toCssPatch` 에서 키를 가려 받습니다 — `--` 로 시작하는
사용자 정의 속성과 `anchor`·`backdrop` 만. **`output.js` 에도 같은 규칙을 둡니다**
(출력 페이지는 의존성 0 이라 로직이 의도적으로 양쪽에 있습니다 — 한쪽만 고치면 안 됩니다).

`SERMON_HOST` 를 설정하는 곳은 **`start.sh` 하나뿐**입니다(전수 확인).
`electron/main.cjs` 는 설정하지 않으므로 설치판에서 `IS_LAN_OPEN` 은 **늘 false** 입니다.
그런데 화면은 이렇게 안내합니다:

| 어디 | 무엇을 시키나 | 설치판에서 |
|---|---|---|
| `TabletAccessCard.tsx:74-82` | `presentation lan` · `source ~/.zshrc` | 터미널·alias 없음 |
| `TabletAccessCard.tsx:94` | `npm run password` | 저장소 없음 |

| `PlanPanel.tsx:2452` | `node scripts/import-kyodoc.ts --apply` | 같음 |

즉 **QR 카드와 접속 암호 기능이 설치판에서는 통째로 죽어 있고**, 안내문은 할 수 없는
일을 시킵니다. 성경 DB 안내는 2026-09-05 에 이미 같은 문제를 겪고
`lib/bible-missing.ts` + `info.packaged` 로 문구를 갈라 놨습니다 — **그 패턴이 여기엔
적용되지 않았습니다.**

**필요한 것** (설계 판단이 필요합니다):
1. 설정 탭에서 **암호 정하기·바꾸기** (라우트 신설 — 루프백 전용, `server/routes/system.ts` 의 `isLocal` 규칙 재사용)
2. 설정 탭에서 **LAN 열기/닫기**. `HOST` 가 모듈 상수라 지금 구조로는 재기동이 필요합니다. 앱 재시작을 시키느냐(간단), 두 번째 리스너를 여느냐(복잡) 가 갈림길입니다
3. 그때까지는 최소한 **문구를 `info.packaged` 로 갈라** '설치판에서는 아직 태블릿을 쓸 수 없습니다' 라고 사실을 말해야 합니다

### 🟢 P-2 자료를 옮기면 승인·검토 상태가 사라진다 — **고쳤다**

**실측** (같은 번들을 내보냈다가 되돌려 넣기 = 다른 PC 로 옮기는 것과 같은 경로):
