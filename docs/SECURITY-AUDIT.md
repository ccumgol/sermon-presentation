## 2. 높음

### H-1. 인증 없이 LAN 전체에 열려 있다 — ✅ 해결됨 (2026-08-16)

**조치**: 기본 바인딩을 `127.0.0.1` 로 바꾸고, 태블릿이 필요할 때만 `npm run start:lan`
(`SERMON_HOST=0.0.0.0`)으로 엽니다. 권고 1번을 그대로 적용했습니다.

**검증** (격리 서버 · 임시 데이터 폴더):

| 모드 | localhost | LAN(192.168.1.190) |
|---|---|---|
| 기본 (`npm start`) | 200 | **연결 거부** |
| 태블릿 (`npm run start:lan`) | 200 | 200 |

기동 로그가 어느 모드인지 항상 알려 주고, LAN 모드에서는 인증이 없다는 경고를 함께 냅니다.
`/api/info` 도 닫혀 있을 때는 태블릿 주소를 주지 않습니다(`lanOpen: false`).
기본값이 되돌아가지 않도록 회귀 테스트 4개를 넣었습니다(`tests/unit/host-binding.test.ts`).

> 남은 것: **태블릿 모드로 열면 여전히 인증이 없습니다.** 그 상태의 위험은 H-2·H-3·M-1 과
> 같으므로, LAN 을 상시로 쓰신다면 권고 4번(접속 암호)이 필요합니다.

**아래는 조치 전 기록입니다.**

**증거**

```
server/config.ts:17   export const HOST = '0.0.0.0';   // 태블릿 접속용
$ curl http://192.168.1.190:7778/api/info   → 200
$ grep -riE "auth|token|password|session" server/   → 인증 코드 없음
```

REST·WebSocket 어디에도 인증·권한 검사가 없습니다. `0.0.0.0` 바인딩은 **태블릿으로 조작**
하려는 의도된 설계(PLAN D5)지만, 그 결과 **같은 네트워크의 모든 기기**가 조작할 수 있습니다.

**실제 피해 시나리오** — 교회 WiFi 에 게스트가 접속해 있는 상황:
`http://<서버IP>:7777/` 을 열면 컨트롤 패널이 그대로 뜨고, 예배 중 화면을 아무 내용으로
바꿀 수 있습니다. 비밀번호를 묻지 않습니다.

**권고 (택1, 위에서부터 권장)**

1. **localhost 로 되돌리고**, 태블릿이 필요할 때만 켠다 — 가장 단순하고 확실
   ```ts
   // server/config.ts
   export const HOST = process.env.SERMON_HOST ?? '127.0.0.1';
   ```
   태블릿을 쓸 때만 `SERMON_HOST=0.0.0.0 npm start`
2. **접속 암호**(공유 토큰)를 둔다 — 첫 접속 시 한 번 입력, 이후 브라우저에 보관.
   REST 는 헤더, WS 는 hello 메시지로 확인
3. 방화벽으로 7777 을 특정 기기에만 연다 (앱 밖의 조치)

### H-2. 인증 없이 데이터를 통째로 지울 수 있다 — 🟡 복구 장치 완료 (2026-08-16)

**조치**: `replace` 는 지우기 **전에** DB 스냅샷을 남깁니다. **백업을 못 뜨면 가져오기를
중단**합니다 — 보호 없이 지우는 것이 이 항목의 위험 자체이기 때문입니다.

`VACUUM INTO` 로 뜹니다. 이 DB 들은 WAL 모드라 `.sqlite` 하나만 복사하면 **WAL 에만 있는
최근 변경이 빠지고**, 세 파일을 복사하면 도중의 쓰기로 어긋난 조합이 남습니다.
`VACUUM INTO` 는 SQLite 가 일관된 단일 파일로 떠 주므로 복원은 그 파일을 제자리에 두면 됩니다.

**검증** (격리 서버에서 위 공격을 그대로 재현):

```
삭제 전 순서표: 7개
→ 무인증 replace 요청 → 200
  백업: songs-before-import-2026-08-17T00-48-03.sqlite
  백업: app-before-import-2026-08-17T00-48-03.sqlite
삭제 후 순서표: 0개
백업 안의 순서표: 주일예배, 수요예배, 새벽기도회, 부흥회, …   ← 그대로 살아 있음
```

테스트 5개(`tests/integration/import-backup.test.ts`) — 백업 생성 · 내용 보존 ·
merge 는 뜨지 않음 · **백업 실패 시 아무것도 지우지 않음** · WAL 내용 포함.

> ⚠️ **삭제 자체는 여전히 막지 못합니다.** 이건 복구 장치일 뿐이고, 무인증 삭제를
> 막는 것은 H-1(완료)과 접속 암호(권고 5)입니다. `data/backups/` 가 자동으로 쌓이므로
> 가끔 정리해 주세요.

**아래는 조치 전 기록입니다.**

**증거 — 격리 서버에서 실제로 실행했습니다**


**왜 가장 위험한가**: `data/songs.sqlite` 는 **git 에 없습니다.** 직접 손보고 승인한 가사가
들어 있고, **되돌릴 방법이 백업뿐**입니다(협업 규칙 0.2). 실수든 악의든 한 번의 요청으로
사라집니다.

**권고**

### H-3. WebSocket 이 Origin 을 보지 않는다 — ✅ 해결됨 (2026-08-16)

**조치**: `verifyClient` 로 Origin 을 검사합니다. 판단은 `lib/origin-check.ts` 의 순수 함수.

| Origin | 판정 | 이유 |
|---|---|---|
| 없음 | 허용 | 비브라우저(OBS 스크립트·도구·테스트). 브라우저는 반드시 보낸다 |
| Host 와 같음 | 허용 | 우리 서버가 내보낸 페이지 — 컨트롤 패널·출력 페이지 |
| `SERMON_ALLOWED_ORIGINS` 에 있음 | 허용 | 리버스 프록시 등 |
| 그 밖 · `null` · 해석 불가 | **차단** | 외부 웹페이지·샌드박스 iframe |

Origin 이 없을 때 허용하는 것이 약점처럼 보이지만 **막아도 얻는 것이 없습니다** —
비브라우저 클라이언트는 Origin 을 마음대로 정합니다. 이 검사는 애초에 *브라우저에 갇힌
스크립트*를 막는 장치이고, 비브라우저 접근은 접근 통제(H-1·접속 암호)의 몫입니다.
대신 OBS·도구·테스트가 끊기지 않습니다.

**검증** (격리 서버 — 감사의 공격을 그대로 재현):

```
악성 웹페이지 (evil.example)    거부됨 (401)
다른 포트 (localhost:3000)      거부됨 (401)
우리 페이지 (localhost:7804)    접속됨
Origin 없음 (OBS·도구)          접속됨

악성 Origin 으로 show 전송 시도 → 연결 자체가 거부돼 메시지를 보낼 수 없음
현재 슬라이드: null   ← 바뀌지 않음
```

**실제 브라우저에서도 확인**했습니다(가장 중요 — 끊기면 예배 중 화면이 멈춥니다).
컨트롤 패널 '서버 연결됨', 출력 페이지 정상, WS 로 `요 3:16` 송출이 화면에 반영됨.
단위 테스트 14개(`tests/unit/origin-check.test.ts`) — 접두사 우회·포트 차이·`null` 포함.

**아래는 조치 전 기록입니다.**

**증거 — 악성 웹페이지를 흉내내 접속했습니다**

```
server/ws.ts:39   const wss = new WebSocketServer({ server, path: '/ws' });   // verifyClient 없음

$ node → new WS('ws://localhost:7778/ws', { origin: 'https://evil.example' })
  연결됨 — 거부되지 않음
  { t:'show', payload:{ kind:'text', lines:['외부에서 넣은 문구'] } } 전송
$ 상태 확인 → 현재 슬라이드: {"kind":"text","lines":["외부에서 넣은 문구"]}
```

**왜 REST 보다 위험한가**: 브라우저의 **CORS 는 WebSocket 에 적용되지 않습니다.**
오퍼레이터가 예배 중 아무 웹사이트나 열어도, 그 페이지의 스크립트가
`new WebSocket('ws://localhost:7777/ws')` 로 붙어 화면을 바꿀 수 있습니다.
REST 는 JSON 본문이라 프리플라이트가 걸려 상대적으로 안전하지만, WS 는 그 보호가 없습니다.

**권고**
```ts
// server/ws.ts — 허용 Origin 만 받는다
const wss = new WebSocketServer({
  server, path: '/ws',
  verifyClient: ({ origin, req }) => isAllowedOrigin(origin, req.headers.host),
});
```
`Origin` 이 없는 접속(OBS 브라우저 소스·네이티브 클라이언트)은 허용해야 하므로,
**`Origin` 이 있을 때만 검사**하는 형태가 맞습니다.

## 3. 중간

### M-1. 무인증 삭제 엔드포인트 5개

```
DELETE /api/songs/:id           곡 삭제

```
H-1 이 해결되면 함께 막힙니다. 내장 프리셋은 409 로 보호되고 있습니다(양호).

### M-2. 본문 한도가 커서 메모리 고갈에 노출

| 라우트 | 한도 | 근거 |
|---|---|---|
| `POST /api/backup/import` | **256MB** | `server/routes/backup.ts:34` |
| `POST /api/backgrounds` | 약 **90MB** (64MB × 1.4) | `server/routes/backgrounds.ts:41` |

base64 는 메모리에 통째로 올라옵니다. 무인증 상태에서 반복 호출하면 서버가 죽고,
**예배 중이면 곧 사고**입니다. 한도 자체는 실사용에 필요해서 정한 값이므로,
접근 통제(H-1)와 요청 수 제한(L-2)으로 막는 편이 맞습니다.

### M-3. `/api/info` 가 경로와 LAN 주소를 공개한다

```json
{ "dataDir": "/Users/…/data", "bibleSourceDir": "/Users/gihyunpark/Desktop/Data/BibleDB",
  "lanAddresses": ["http://192.168.1.190:7777/"], "songCount": 1202 }
```
사용자 계정 이름과 내부 IP 가 무인증으로 나갑니다. 그 자체로 침해는 아니지만
**다음 공격의 정찰 정보**입니다. 컨트롤 패널에 필요한 값이므로 H-1 해결 후에는 문제가 없습니다.

| 1 | ✅ **기본 바인딩을 `127.0.0.1` 로**, 태블릿 쓸 때만 환경변수로 연다 | 한 줄 + 문서 | H-1·H-2·M-1·M-3 대부분 |
| 2 | ✅ **`replace` 가져오기 전 서버가 자동 백업** | 수십 줄 | H-2 의 피해 복구 |
| 3 | ✅ **WS Origin 검사** (Origin 이 있을 때만) | 십여 줄 | H-3 |
| 4 | **배경 삭제 API + 총량 상한** (감사 이후 발견 — 아래 S-1) | 수십 줄 | 디스크 고갈 → 가사 손실 |
| 5 | LAN 을 계속 쓴다면 **접속 암호** | 하루 정도 | H-1 전부 |
| 6 | 간단한 요청 수 제한 | 반나절 | M-2·L-2 |

> 2·3 의 순서를 감사 원안에서 바꿨습니다(Agent C). Origin 검사는 화면이 바뀌는 피해지만
> `replace` 는 **되돌릴 수 없는 데이터 손실**이라 복구 장치가 먼저 필요합니다.

### S-1. 배경 업로드에 총량 제한·삭제가 없다 (감사 이후 발견, Agent C)

`POST /api/backgrounds` 는 파일당 64MB 상한만 두고 **총량·개수 제한이 없으며, 삭제
엔드포인트가 아예 없습니다.** 격리 서버에서 확인했습니다.

```
업로드 3건 → 200 · 파일 3개 누적
DELETE /api/backgrounds/flood-1.png → 404   (삭제 API 없음)
```

M-2 는 **메모리** 고갈을 다루지만 이건 **디스크**입니다. 디스크가 차면 같은 볼륨의
`data/songs.sqlite` 쓰기가 실패해 **손보고 승인한 가사가 저장되지 않거나 손상될 수**
있습니다. 메모리는 재시작하면 끝이지만 이건 데이터가 걸립니다.
같은 이름으로 올리면 말없이 덮어쓰는 것도 함께 고쳐야 합니다.

> ⚠️ 1번은 **지금 태블릿으로 조작하고 계신다면 그 경로를 막습니다.**
> 쓰고 계신 방식을 알려 주시면 그에 맞춰(예: 기본은 localhost + 태블릿 모드 스위치) 만들겠습니다.
