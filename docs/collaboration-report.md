## 0. 이 문서 사용 규칙 (중요)

작업을 시작·완료할 때 **이 문서를 먼저 읽고, 끝나면 갱신**해 주세요. 목적은 **중복 작업과
충돌 방지**입니다.

1. **착수 전**: 4장(작업 보드)에서 그 항목이 `🔴 미착수` 인지 확인하고, `🟡 진행중`으로 바꾸고
   본인 이름(Agent 명)과 날짜를 적습니다.
2. **완료 후**: `🟢 완료`로 바꾸고 **검증 방법과 결과**를 3장에 한 줄 남깁니다.
   (주장만 쓰지 말고 "무엇으로 확인했는지" 적어주세요)
3. **파일 충돌 주의**: 5장 "파일별 점유 현황"에서 다른 Agent가 만지는 파일과 겹치면
   먼저 6장 "인계 메모"에 남기고 조율합니다.
4. **커밋 정책**: Agent 가 작업 완료 후 **직접 커밋·푸시합니다.**
   - 논리적 단위로 나눠 커밋하고(성격이 섞이면 분리), 메시지에 **원인·조치·검증**을 담습니다.
   - ⚠️ **푸시 전 점검 필수**: `git diff --name-only origin/main..HEAD` 로
     `data/`·`.claude/settings.local.json` 이 포함되지 않았는지 확인.
   - 협업 중이므로 푸시 실패 시 `git pull --rebase` 후 재시도합니다.
   - **이력 재작성(force push, filter-repo)은 사용자 승인 필요** — 다른 Agent 작업을 깨뜨릴 수 있음.
5. **착수할 때 "복구 정보"를 먼저 쓴다** (⚠️ 가장 중요 — 아래 0.1 참고).
   사용량 만료·크래시는 예고 없이 오므로, **끝난 뒤 쓰는 기록은 남지 않습니다.**
6. **사용자 데이터를 되돌리기 전에 반드시 묻는다** (⚠️ 이 프로젝트 고유 — 아래 0.2 참고).

## 0.1 중단(사용량 만료·크래시·강제 종료) 대응 규칙 ★필수

Agent 작업은 **토큰/사용량 소진, 세션 만료, 크래시**로 언제든 중간에 끊길 수 있습니다.
그 경우 "완료 후 갱신" 규칙만 있으면 보드에 `🟡 진행중` 만 남아, 다른 Agent 가
**"누가 하는 중이니 손대지 말자"** 고 오해해 작업이 정지합니다.

### 규칙 A — 착수 즉시 3줄을 먼저 기록 (선행 기록)
작업을 시작하면 **코드를 만지기 전에** 8장(진행 중 작업 로그)에 다음을 씁니다.
```
- [시작 2026-08-15 14:30 / Agent B] 찬미예수 2000 곡집 가져오기
  계획: scripts/import-songbook-folder.ts 신규 / 폴더 규약(번호 제목.txt) 파서 재사용
  다음 단계: 파서 단위테스트 → 미리보기 실행 → 사용자 확인 → --apply
```
중단돼도 **이 기록이 남아** 다음 Agent 가 이어받을 수 있습니다.

### 규칙 B — 긴 작업은 단계마다 한 줄 갱신
30분 이상 걸릴 작업은 단계가 끝날 때마다 `다음 단계:` 줄만 고칩니다.
(마지막으로 갱신된 지점이 곧 **중단 지점**입니다)

### 규칙 C — 이어받는 Agent 의 판정 절차
`🟡 진행중` 인데 담당자가 응답 없거나 오래됐다고 판단되면 **아래 근거로 직접 확인**하세요.
추측하지 말고 실제 상태를 보고 판단합니다.

```bash
# 1) 미커밋 변경 = 진행 중이던 흔적 (무엇을 만지고 있었는지)
git status --short
git diff                     # 어디까지 고쳤는지

# 2) 파일 수정 시각 = 마지막 활동 시점 (중단 시각 추정)
ls -lt lib/*.ts server/**/*.ts src/control/**/*.tsx scripts/*.ts docs/*.md | head

# 3) 남은 잔여물 확인
git stash list               # 중단 전 stash 했을 수 있음
git branch --no-merged main  # 미병합 작업 브랜치

# 4) 코드가 실제로 동작하는 상태인지 (반쯤 고친 상태일 수 있음)
npx tsc --noEmit
npx vitest run
```

**판정 기준 (제안)**
| 상황 | 판정 | 조치 |
|---|---|---|
| 미커밋 변경 있음 + 파일 수정이 **수 시간 이상 전** | 중단됨 | 8장 로그를 읽고 이어받기. 상태를 `🟡 진행중(인계: 본인)` 으로 갱신 |
| 미커밋 변경 없음 + 보드만 `🟡` | **착수 직후 중단** | 그 항목은 사실상 미착수 → `🔴` 로 되돌리고 새로 시작 |
| 테스트/타입검사 실패 | **반쯤 고친 상태** | 먼저 그 부분을 완성하거나 되돌린 뒤 진행 (사용자에게 보고) |
| 판단이 애매함 | — | **사용자에게 확인** (임의로 되돌리지 말 것) |

### 규칙 D — 되돌리기는 사용자 승인 후
중단된 작업의 미커밋 변경을 **버리는 것(`git checkout --`, `git stash drop`)은 사용자 승인
없이 하지 않습니다.** 다른 Agent 의 미완성 작업일 수 있고, 커밋 전이라 복구가 불가능합니다.

### 규칙 E — 사용자가 할 수 있는 최소 조치
Agent 가 갑자기 멈췄을 때 사용자는 다음 한 줄만 남겨도 충분합니다.
```
- [중단 2026-08-15 15:10] Agent B 사용량 만료로 중단. 위 항목 이어받을 Agent 필요.
```

## 0.2 사용자 데이터 취급 규칙 ★이 프로젝트 고유·필수

**이 프로젝트에서 가장 위험한 실수는 코드 버그가 아니라 사용자 데이터를 지우는 것입니다.**
실제로 한 번 일어났습니다(3.2 사고 기록).

이 프로젝트의 데이터(`data/songs.sqlite`)에는 **사용자가 UI 로 직접 손본 가사**가 들어 있고,
**git 에 들어가지 않으므로 되돌릴 방법이 백업뿐**입니다.

### 지켜야 할 것

1. **사용자는 Agent 가 작업하는 동안에도 병행해서 데이터를 편집합니다.**
   백업과 DB 가 다르다고 해서 "내 테스트 흔적"이라고 단정하지 마세요.
2. **되돌리기 전에 반드시 묻습니다.** 데이터를 원상복구하는 작업은 사용자 승인 후에만.
3. **파괴적 스크립트 실행 전 백업**:
   ```bash
   cp data/songs.sqlite "data/backups/songs-before-$(date +%Y%m%d-%H%M%S).sqlite"
   ```
4. **`lines_source = 'manual'`(승인) 은 사람의 작업 표시입니다.**
   자동 스크립트뿐 아니라 **Agent 도** 이 곡을 건드리지 않습니다.
   찬양 탭 목록에 초록색 `승인` 표로 보입니다.
5. **자기가 만든 변경만 목록으로 관리**하고, 정리할 때 그 목록에 있는 것만 되돌립니다.
6. **원본 성경 DB(`~/Desktop/Data/BibleDB`)와 찬양 자료 폴더(`~/Desktop/Data/Praise`)는
   읽기 전용으로만 엽니다.** 절대 쓰지 않습니다.

### 스크립트는 미리보기가 기본
데이터를 바꾸는 스크립트는 모두 **미리보기가 기본이고 `--apply` 를 붙여야 실제로 씁니다.**
새 스크립트를 만들 때도 같은 규칙을 따르세요.

```bash
npm run lyrics:realign          # 미리보기 (아무것도 쓰지 않음)
npm run lyrics:realign -- --apply
```

### 3.2 ⚠️ 사고 기록: 사용자가 직접 수정한 가사를 되돌림 (2026-08-14, 복구됨)

**같은 실수를 반복하지 않기 위해 남깁니다. 0.2 규칙이 여기서 나왔습니다.**

- **무슨 일**: 브라우저 검증 중 백업과 DB 를 대조해 나온 차이를 **"내 테스트 흔적"으로
  단정하고 되돌렸습니다.** 실제로는 사용자가 병행 작업으로 직접 고치고 승인한
  가사 4곡과 승인 표시 6곡이었습니다.
- **왜 막히지 않았나**: "백업과 다르면 내가 만든 것"이라는 전제를 세웠고, 사용자가
  같은 시간에 작업할 가능성을 계산에 넣지 않았습니다.
- **복구**: SQLite WAL 파일(`data/songs.sqlite-wal`)에 남아 있던 옛 페이지에서 원문을
  찾아 복원했습니다. 네 곡 모두 **잘려 있던 단어를 붙인 수정**이었습니다
  (`영원/무궁하기까지`, `돌려/보내세`, `영광/받으옵소서`, `온누리/다스리시는`).
- **교훈 / 다른 Agent 가 지킬 것**: 0.2 참고. 요약하면
  1. 사용자는 Agent 와 **동시에** 데이터를 편집한다
  2. 되돌리기 전에 **묻는다**
  3. 파괴적 작업 전 **백업**한다
  4. `lines_source='manual'` 은 자동 작업뿐 아니라 **Agent 도** 건드리지 않는다

### 3.3 곡집 구조 · 가사 줄나눔 (2026-08-13~14)

- **곡집을 행으로**: `song_entries` 다대다 → 시리즈를 스키마 변경 없이 추가.
- **후렴 병합**: 원본이 인라인이던 것을 되돌림(586곡). 절 끝 어절이 후렴을 수식하는
  97곡에서 문장이 끊겨 있었음.
- **절 간 운율 정렬**: 같은 곡의 절들은 같은 멜로디라는 제약으로 공통 행 구조를 찾음.
  새256 이 `9.9.9.9`, 새305 가 `8.6.8.6`(Common Meter)으로 정확히 일치.
- **순위 규칙은 측정으로 결정**: 1,146곡에 네 규칙을 돌려 비교(`npm run measure:meter`).
  짝수 강제의 대가는 꼬리조각 0.38%p, 얻는 것은 홀수 행 286곡 → 0곡.

### 3.4 헬라어 자간 벌어짐 — 폰트 체인 (2026-08-14)

- **데이터는 정상**이었음. 원인은 폰트 체인이 총칭 `serif` 로만 끝나, 총칭 폰트가
  다음절 그리스어(U+1F00 대역)를 못 덮어 **글자마다 다른 폰트로 대체**된 것.
- 판별법: **다음절 폭 ÷ 단음절 폭 비율**. 1.02 면 자체 글리프, 1.10 이면 대체.
- 총칭 앞에 Times New Roman 을 넣어 819.6px → 526.6px, 비율 1.02 로 정상화.
- **프리셋만 고쳐서는 부족했음** — 저장된 사본은 JSON 으로 굳어 있어, 초기화 때

### 작업 시 지켜야 할 이 프로젝트의 관례

- **추측 말고 실측.** 이 프로젝트의 거의 모든 판단은 측정에서 나왔습니다
  (ESV 판본 비교, 운율 순위 규칙, 폰트 대체 비율, 스크롤바 폭).
  숫자 없이 "좋아 보인다"로 정하지 마세요.
- **화면을 스스로 비우지 않습니다.** 서버가 죽어도 출력 페이지는 마지막 내용을 유지합니다.
  예배 중 검은 화면이 최악의 결과입니다.
- **자동 결과는 제안입니다.** 사람이 확인(승인)해야 확정됩니다.
- **본문을 임의로 고치지 않습니다.** 성경은 `text_raw` 에 원문을 남기고, 가사는
  어절 경계에서만 끊어 **글자가 바뀌지 않음**을 테스트로 고정합니다.
- **출력 페이지는 의존성 0.** OBS 내장 브라우저(CEF)에서 초기화가 실패할 지점을 없앱니다.
- **문서 동시 갱신**: 동작을 바꾸면 README·PLAN 의 해당 문구도 고칩니다.
- **검증 3종은 항상 통과**:
  ```bash
  npx tsc --noEmit && npx vitest run && npx vite build
  ```
- **서버 재기동 필수**: TypeScript 를 네이티브로 실행하므로 **코드를 고치면 서버를
  재시작**해야 반영됩니다. 옛 프로세스가 7777 을 잡고 있으면 구버전이 응답해
  "수정이 반영되지 않은 것처럼" 보입니다(실제로 여러 번 겪음).
  ```bash
  lsof -ti:7777 | xargs kill -9
  ```
- **브라우저 확인은 직접**: 사용자에게 "확인해 보세요"라고 하지 말고 Agent 가 직접
  띄워서 재고 스크린샷으로 보여 줍니다.
