## 1. 왜 다시 만드는가

'예배 순서'는 **실제로 가장 많이 쓰게 될 화면**입니다. 성경·찬양 탭은 한 종류를 깊게
다룰 때 편하지만, 예배 진행은 **찬양 → 성경 → 광고 → 인용구**가 섞여 순서대로 흐릅니다.
지금은 그 흐름을 한 화면에서 다룰 수 없습니다.

### 현재의 구체적인 한계

| # | 한계 | 결과 |
|---|---|---|
| 1 | 항목을 **미리보기 없이** 추가한다 (참조 문자열만 입력) | 맞는 본문인지 예배 전에 확인 못 함 |
| 2 | **'예배용으로 올리기' 전체 덱**만 있다 | 준비해 둔 것 중 **골라서** 송출 불가 |
| 3 | 광고(text) **추가 UI 가 없다** (공백만 있음) | 광고는 성경/찬양 탭에도 없어 아예 못 넣음 |
| 4 | 인용구를 **잠깐 띄웠다 가리는** 흐름이 없다 | 설교 중 인용구를 띄우면 계속 남아 있음 |
| 5 | **포커스가 어디인지** 알 수 없다 | 예배 중 키를 눌렀을 때 무엇이 움직일지 예측 불가 |
| 6 | 항목 카드가 크다 (60px+) | 10항목이 한 화면에 안 들어옴 |

### 설계 목표

1. **한 화면에서 전부** — 성경 검색·찬양 검색·광고 입력을 이 탭 안에서
2. **준비와 실행의 분리** — 눌러도 바로 안 나가고, 확인한 뒤 송출
3. **조밀한 구조** — 성경/찬양 탭의 큰 카드가 아니라 목록형 행
4. **포커스가 눈에 보인다** — 선택된 것과 **송출 중인 것**을 다른 색으로

없애고 좌측에 인라인 추가 바**를 둡니다. 라이브러리를 오가는 왕복이 이 앱에는 불필요합니다

## 3. 상호작용 모델 — 준비와 실행

**가장 중요한 결정입니다.** 지금은 '전체 올리기' 하나뿐이라 골라 쓸 수 없습니다.

### 두 상태를 명확히 구분

| 개념 | 표시 | 뜻 |
|---|---|---|
| **선택(커서)** | 파란 테두리 | 지금 보고 있는 항목. **화면에 나가지 않음** |
| **송출 중** | 빨간 점 + 배경 | 실제로 OBS 에 나가고 있는 슬라이드 |

FreeShow 도 이 둘을 나눕니다. 항목을 눌러도 바로 안 나가야 예배 중에 안전합니다.

### 흐름

```
항목 클릭 (또는 ↑↓)     → 선택만. 우측에 슬라이드가 뜬다. 화면은 그대로.
슬라이드 클릭 / Enter    → 그 슬라이드를 송출.
←→ / Space              → 송출 중인 덱 안에서 이동.
```

### '올리기'와의 관계

`예배용으로 올리기`를 누르면 지금처럼 **전체를 한 덱으로** 만듭니다(항목 경계 = `groups`).
이후에는 **항목 클릭 = 그 그룹의 시작으로 점프**가 되어, 준비와 실행이 하나로 이어집니다.

아직 올리지 않았다면 항목 클릭 → Enter 는 **그 항목만 단독 송출**합니다.
둘 다 필요합니다 — 순서대로 진행할 때와, 순서를 벗어나 급히 띄울 때.

### 인용구 잠깐 띄우기

설교 중 인용구는 **띄웠다 가려야** 합니다. 세 가지를 둡니다.

1. 항목 행의 `▶` 버튼 — 바로 송출 (선택을 거치지 않음)
2. **`직전으로` 버튼** — 인용구를 띄우기 직전 화면으로 되돌림 (새로 추가)
3. 기존 `B`(블랙 — 텍스트만 숨김) / `Esc`(복구) 유지

`직전으로`가 핵심입니다. 지금은 인용구를 띄우면 설교 본문 화면으로 돌아갈 방법이
"그 항목을 다시 찾아 누르기"뿐입니다.

## 4. 데이터 모델 변경

기존 `CueItem` 유니온에 **최소한만** 더합니다.

```ts
// 새 항목 종류 — 그룹 머리글. 슬라이드를 만들지 않는다.
| { id: string; type: 'divider'; label: string }

// text 항목에 용도 구분 (아이콘·기본 템플릿만 달라진다)
| { id: string; type: 'text'; content: string;
    variant?: 'notice' | 'quote';    // 광고 | 인용구
    templateId?: number; note?: string }
```

- `divider` 는 `lib/plan-deck.ts` 에서 **슬라이드를 만들지 않고 건너뜁니다.**
  `groups` 인덱스가 어긋나지 않도록 테스트로 고정합니다.
- `variant` 는 표시용입니다. 저장된 순서표의 하위 호환이 깨지지 않습니다(없으면 `notice`).
- `ServicePlan` 스키마(테이블)는 **바뀌지 않습니다** — `items` 가 JSON 이므로.

## 5. 포커스와 단축키

### 포커스 영역
좌(순서 목록) · 우(슬라이드) 두 영역이 키보드 포커스를 가질 수 있습니다.
**포커스가 있는 열은 테두리가 밝아집니다.** `Tab` 으로 오갑니다.

### 단축키

| 키 | 좌(순서) 포커스 | 우(슬라이드) 포커스 |
|---|---|---|
| `↑` `↓` | 항목 이동 | 줄 이동 |
| `←` `→` | — | 슬라이드 이동 |
| `Enter` | 선택 항목 **송출** | 선택 슬라이드 **송출** |
| `Tab` | 우측으로 | 좌측으로 |

전역(포커스 무관): `Space` 다음 · `B` 블랙 · `Esc` 복구 · `PgDn/PgUp` 항목 단위

⚠️ **기존 전역 `←→`(슬라이드 이동)와 충돌합니다.** 좌측 목록에 포커스가 있을 때는
`←→` 를 전역에 넘기고, 우측에 있을 때만 가로챕니다. 입력창 포커스 시에는 지금처럼 전부 무시.

좌측 열 아래에 고정. 타입 버튼을 고르면 **입력창 하나의 동작이 바뀝니다.**

| 버튼 | 입력 | Enter 동작 |
|---|---|---|
| 📖 성경 | `요 3:16` | 파싱 확인(초록/빨강) 후 추가. 후보가 여럿이면 버튼으로 |
| 🎵 찬양 | `새 305` · `나 같은 죄인` | 검색 결과 드롭다운 → 선택 시 추가 |
| 📝 광고 | 여러 줄 텍스트 | 추가 |
| 💬 인용구 | 여러 줄 텍스트 | 추가 (`variant: 'quote'`) |
| ⬛ 공백 | — | 즉시 추가 |
| ▾ 구분 | 그룹 이름 | 머리글 추가 |

성경·찬양 검색은 **기존 API 를 그대로** 씁니다 (`/api/bible/parse`, `/api/songs`).
새 서버 작업은 없습니다.

## 8. 확인이 필요한 것 (사용자 결정)

> 답이 정해지면 이 절을 지우고 본문에 반영합니다.

1. **'올리기' 를 유지할지, 자동으로 할지**
   항목을 추가·수정할 때마다 자동으로 덱을 다시 만들면 버튼이 필요 없지만, 성경 조회와
   실측 분할이 들어가 **항목이 많으면 몇 초 걸릴 수 있습니다.** 예배 직전에 그게 도는 것이
   더 위험할 수 있어 지금은 수동 버튼을 유지하는 쪽으로 제안했습니다.

2. **`직전으로` 의 범위**
   인용구를 띄우기 직전 **슬라이드 한 장**으로 돌아갈지, **덱 전체 상태**로 돌아갈지.
   전자가 단순하고 예측 가능합니다.

3. **그룹(구분) 을 미리 만들어 둘지**
   `예배 부름 / 찬양 / 말씀 / 광고` 같은 기본 그룹을 새 순서표에 자동으로 넣을지,
   매번 직접 만들지.

4. **광고와 인용구를 정말 나눌지**
   지금 제안은 `variant` 로만 구분(아이콘·기본 템플릿). 완전히 같게 둬도 됩니다.

5. **드래그로 순서 바꾸기**
   지금은 `↑↓` 버튼입니다. 드래그를 넣으면 편하지만 구현·테스트가 늘어납니다.
   1차에서는 빼고, 쓰면서 필요하면 넣는 것을 제안합니다.
