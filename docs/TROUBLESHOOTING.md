## 2. 지금도 만날 수 있는 문제

### 2.1 화면에 아무것도 안 나온다 / OBS 가 미연결이다

**확인**: `/api/info` 의 `connections.output` 이 `0` 인가.

**가장 흔한 원인**: 서버가 내려간 동안 OBS 소스를 새로고침했다. 그러면 CEF 가 페이지를
못 받아 '연결 거부' 오류 화면에서 멈추고, **우리 JS 가 아예 실행되지 않아 자동 재연결도
못 합니다.** 서버가 나중에 떠도 영영 붙지 않습니다.

**조치**: 서버가 완전히 뜬 것을 확인한 뒤 → OBS 브라우저 소스 더블클릭 → **현재 페이지 새로고침**.

**그 밖에** 확인할 것:
- 소스가 여러 개면 **URL 이 `http://localhost:7777/output/?layer=main` 인 소스**를 새로고침했는지
- OBS 설정에서 `표시되지 않을 때 소스 종료` 가 꺼져 있는지

```bash
# OBS 가 실제로 7777 에 붙어 있는지 (프로세스로 확인)
for p in $(lsof -ti:7777); do ps -o pid,comm -p $p | tail -1; done
```

### 2.2 새로 만든 기능이 화면에 안 나온다 (오류도 없이 "그대로")

**원인**: OBS 안의 출력 페이지가 **옛 판**입니다. 서버를 재시작해도 그 페이지는
WebSocket 만 다시 붙고 **JS 는 메모리에 있던 것 그대로**입니다. 권장 설정상
'장면 활성화 시 새로고침' 도 꺼져 있어 저절로 갱신되지 않습니다.

옛 판은 모르는 슬라이드 종류를 받으면 **화면을 비우지 않고 이전 내용을 유지**하도록
만들어져 있어(예배 중 검은 화면 방지), 검은 화면이 아니라 **"안 바뀜"** 으로 나타납니다.

**조치**: OBS 브라우저 소스 새로고침. 지금은 컨트롤 패널이 **노란 배너로 먼저 알려 줍니다.**

**무엇을 고쳤을 때 무엇을 다시 해야 하는가**:

| 고친 곳 | 서버 재시작 | OBS 새로고침 |
|---|:---:|:---:|
| `server/`, `lib/`, `shared/` | ✅ | — |
| `src/control/` (패널) | ✅ (빌드 포함) | — |
| `public/output/` (출력 페이지) | — | ✅ |
| 폰트 설치 | — | ✅ **OBS 완전 종료 후 재실행** |

```bash
lsof -ti:7777 | xargs kill -9 && npm start
```

### 2.3 폰트를 설치했는데 안 잡힌다

**원인 두 가지.**

1. **이름이 실제와 다르다.** 파일이 `BareunBatangOTFPro-3.otf` 라고 `"BareunBatangOTFPro 3"`
   로 적으면 어디에도 안 걸려 **조용히 고딕으로 대체**됩니다. 화면은 멀쩡해 보이고,
   축소된 화면에서는 구분도 안 됩니다.
2. **실행 중인 프로그램이 새 폰트를 못 본다.** 브라우저·OBS 는 **시작 시점의 폰트 목록**을
   들고 있습니다. 설치 후에 켠 프로그램만 그것을 봅니다.

**조치 — 먼저 설정 탭**: **설정 → 화면 폰트** 가 권하는 폰트 두 개(`Noto Sans KR`·
`Noto Serif KR`)의 설치 여부를 **재서** 알려 줍니다. `설치됨` 이 아니면 거기서 받으세요.
설치한 뒤 **OBS 를 완전히 종료했다 다시 실행**하고, 이 탭을 새로 고쳐 표시가 바뀌는지 봅니다.

**직접 적은 폰트라면**: 템플릿 탭 폰트 칸 아래의 **`실제 사용:`** 표시를 보세요.
원하는 폰트가 아니면 이름이 틀렸거나 설치가 안 된 것입니다.

> **굵은 글씨를 쓰므로 Bold 도 함께 설치하세요.** 없으면 브라우저가 억지로 굵게 그려
> 글자가 뭉개집니다.

파일에 적힌 진짜 이름은 이렇게 확인합니다.

```bash
python3 - "$HOME/Library/Fonts/NotoSerifKR-Bold.ttf" <<'PY'
import sys,struct
d=open(sys.argv[1],'rb').read()
num=struct.unpack('>H',d[4:6])[0]; off=12
for i in range(num):
    tag=d[off:off+4]; o,l=struct.unpack('>II',d[off+8:off+16]); off+=16
    if tag==b'name':
        cnt,so=struct.unpack('>HH',d[o+2:o+6])
        for j in range(cnt):
            p=o+6+j*12
            pid,eid,lid,nid,ln,ofs=struct.unpack('>HHHHHH',d[p:p+12])
            if nid==1 and pid==3 and lid==1033:
                print('family =', d[o+so+ofs:o+so+ofs+ln].decode('utf-16-be','ignore'))
PY
```

### 2.4 항목 설정을 바꿨는데 화면이 그대로다

**원인**: **순서표 전체를 올린 상태**입니다. 올릴 때 슬라이드를 한 번 만들어 두고 예배 중에는
다시 계산하지 않습니다(그래야 조회 실패·지연이 없습니다).

**조치**: **예배용으로 올리기** 를 다시 누릅니다. `▶` 로는 안 됩니다 — 올라간 덱 안에서
자리만 옮기므로 옛 슬라이드가 그대로 나옵니다. 그 안내가 항목 칸에도 표시됩니다.

**단독 송출 중인 항목**(순서표 전체를 올리지 않고 그 줄만 `▶` 로 띄운 경우)은
고치는 즉시 화면이 따라옵니다 — 교독문·전례문의 폰트·크기·배경·판본·화면 넘김,
찬양의 표시 언어·화면 넘김, 순서 표시의 담당자 크기·글자 조정 모두 그렇습니다.

조정 작업은 올리기 **전에** 하는 편이 편합니다.

### 2.4.1 항목을 눌렀는데 화면이 바뀐다

**원인**: 정상입니다. 성경·찬양·교독문·전례문의 머리 줄을 누르면 **제목 한 줄**이 나갑니다
(회중이 다음을 준비하도록). 본문은 그 안의 장을 누르거나 `▶` 를 눌러야 나갑니다.

**끄려면**: 예배 순서 탭 → **기본 설정** → `항목을 누르면 제목 띄우기` 를 **끔**.
바꾼 뒤 `템플릿 업데이트` 또는 `순서 저장하기` 를 눌러야 남습니다.

**2026-08-19 이전 판**에서는 프리셋을 고쳐 저장하면 **강제로 사본**이 만들어졌습니다
(같은 이름의 사본이 여럿 생긴 원인입니다).

**지금은** 프리셋을 그 자리에 덮어씁니다. 목록에 `[프리셋·고침]` 으로 표시되고
**원본은 프로그램 코드에 남아 있어** `원본 불러오기` 로 언제든 되돌아옵니다.

### 2.4.3 번역 가사를 폴더로 넣었는데 일부가 안 들어갔다

미리보기가 이유를 알려 줍니다. 흔한 셋:

| 메시지 | 뜻 |
|---|---|
| `곡을 찾지 못했습니다` | 그 곡집에 그 번호가 없습니다. 파일 이름(번호)을 확인하세요 |
| `같은 번호의 곡이 2개입니다` | 원본 곡집에 같은 번호가 둘 있습니다 (실제 35건). 사람이 골라야 하므로 넣지 않습니다 — [KNOWN-DATA-ISSUES §4.5](KNOWN-DATA-ISSUES.md) |
| `규약에 맞지 않아 건너뛴 파일` | `언어/곡집/번호.txt` 형태여야 합니다. 파일 이름이 제목이면 안 됩니다 |

**한국어(`ko`) 폴더는 받지 않습니다.** 승인한 가사를 파일로 덮어쓰지 않기 위해서입니다 —
한국어는 찬양 탭에서 고칩니다.

### 2.4.4 교독문 번호를 찾았는데 내용이 다른 글이다

**교독문은 두 벌이 들어 있습니다** — 통일찬송가용 76편, 새찬송가용 137편. **번호가 같아도
다른 글**입니다 (15번: 통일 `시편 51편` / 새 `시편 27편`).

1. 교독문 추가 칸 위의 **`통일찬송가용` / `새찬송가용`** 버튼에서 쓰려는 쪽이 눌려 있는지 봅니다.
   버튼에 편수가 나옵니다 (76 / 137).
2. 이미 넣은 항목이라면 항목을 눌러 상세 칸의 `새찬송가용 · 15번` 표시를 확인합니다.
3. 다른 쪽을 쓰려면 **항목을 지우고 다시 넣습니다.** 상세 칸에서 찬송가를 바꿀 수 없게 해 둔
   것은 일부러입니다 — 바꾸면 내용이 통째로 다른 글이 되므로, 무엇을 고르는지 목록에서 눈으로
   보고 넣는 편이 안전합니다.

**예전에 만든 순서표**의 교독문은 모두 **통일찬송가용**으로 열립니다 (항목에 표시가 없으면
통일찬송가용으로 봅니다). 새찬송가용을 넣은 항목에만 표시가 붙습니다.

> 서버를 켠 채로 새찬송가 교독문을 반입했다면 **서버를 한 번 껐다 켜세요.** 표의 구조가
> 바뀌었으므로, 켜져 있던 서버는 번호로 찾을 때 두 벌 중 어느 것을 집을지 알지 못합니다.

### 2.4.5 프로젝터 창 — 주소줄·제목줄이 안 없어진다 ★

**화면을 한 번 클릭하세요.** 그러면 전체 화면이 되어 주소줄·제목줄·탭·창 테두리가 전부
사라집니다. `F` 도 같습니다.

`F` 가 안 먹었던 이유는 대개 **키보드 초점이 브라우저 쪽에 있어서** 입니다 — 창을 열고
바로 `F` 를 누르면 페이지가 그 키를 받지 못합니다. 그래서 **클릭**으로도 되게 했습니다.

- 웹페이지가 브라우저 주소줄을 지우는 방법은 **없습니다**(피싱 방지). 전체 화면이
  유일한 길이고, 브라우저 규칙상 **사람이 누르는 순간에만** 됩니다.
- 다음에 열 때는 **첫 클릭이나 첫 키 입력에서 저절로** 전체 화면이 됩니다.
- 매주 쓰신다면 **앱으로 설치**하세요 — 애초에 주소줄이 없는 창으로 열립니다
  (크롬 주소창 오른쪽 ⊕, 또는 메뉴 → 캐스트·저장 및 공유 → 페이지를 앱으로 설치).
  설정 탭의 **프로젝터로 띄우기** 카드에 같은 안내가 있습니다.
- 창으로 돌아가려면 `Esc` 나 막대의 **전체 화면 해제** — 그러면 다음에도 창으로 열립니다.

### 2.4.5.1 프로젝터 창 — 조작이 안 보인다

**조작 막대가 안 보이는 것은 정상입니다.** 마우스를 움직이면 위쪽에 나오고, 2.5초 동안

### 2.4.6 프로젝터에 글씨가 잘려 나온다

막대에 **⚠ 글이 화면을 넘칩니다** 가 떠 있는지 보고, `−` 로 줄이세요.

'글자 크기가 안 바뀐다' 가 되기 때문입니다(그 증상을 실제로 겪었습니다 — 3.4 참고).
길이가 늘 넘치면 그 항목의 **화면 넘김 단위**를 더 잘게 두세요.

### 2.4.7 프로젝터 창이 'OBS 연결됨' 에 안 잡힌다

**정상입니다.** 프로젝터·강사 모니터·미리보기는 우리가 띄우는 브라우저 창이라 OBS
출력 수와 따로 셉니다. 섞으면 'OBS 연결됨' 표시가 거짓이 됩니다.

프로젝터가 붙어 있으면 **프로젝터** 버튼에 초록 점이 붙습니다. 그것으로 확인하세요.
같은 이유로 이 창에는 '브라우저 소스를 새로고침하라' 경고가 뜨지 않습니다 — 그 창은
`F5` 로 새로고침하면 됩니다.

### 2.4.8 프로젝터 화면이 활성 템플릿을 안 따른다

**일부러 그렇습니다.** OBS 는 카메라 영상 위에 얹는 '하단 두 줄'이 맞고, 프로젝터는
벽에 큰 글씨가 맞습니다. 둘이 동시에 필요하므로 프로젝터에는 늘
**'전체 — 성경·찬송 겸용'** 을 보냅니다.

- 프로젝터의 글자 크기·배치를 바꾸려면 템플릿 탭에서 **'전체' 프리셋**을 고치세요
- 그 창에서 바로 키우려면 `+ −` 를 쓰세요 (저장됩니다)
- 순서표에서 항목마다 지정한 템플릿(교독문·순서 표시 등)도 프로젝터에서는 무시됩니다

### 2.4.9 인용구에 글자를 쓸 수 없다 / 옛 인용구가 이상하다

**인용구(💬)는 2026-08-20 부터 성경 절만 받습니다.** 광고(📝)와 기능이 똑같아서
바꿨습니다. 자유 글자는 **📝 광고**를 쓰세요 (여러 줄도 됩니다).

- 인용구 칸은 이제 **한 줄 참조 입력**입니다 (`창 1:1-6`). 성경처럼 참조가 맞는지
  아래에 표시되고, `— 절마다 낱개 항목이 됩니다` 가 함께 나옵니다.
- 옛 순서표에 남아 있는 자유 글자 인용구는 **그대로 나갑니다** — 광고처럼 글자가
  화면에 뜹니다. 망가지지 않았습니다.
- 옛 것을 한꺼번에 지우려면:

```bash
node scripts/remove-text-quotes.ts
```

미리보기가 기본입니다. 무엇을 지울지 내용까지 보여 준 뒤, `--apply` 를 붙이면
스냅샷을 뜨고 지웁니다.

### 2.4.10 인용구를 눌렀는데 화면이 안 바뀐다

인용구는 **펼치기가 없습니다** — 절 하나가 화면 하나이므로 줄을 한 번 클릭하면 바로
나갑니다. `▸` 가 없는 것이 정상입니다.

그래도 안 바뀌면:

- **순서표 전체를 올린 상태**라면, 클릭은 올라간 덱 안에서 **자리만 옮깁니다.**
  올린 뒤에 넣은 인용구는 덱에 없으므로 `예배용으로 올리기` 를 다시 누르세요 (2.4 참고).
- 서버 연결이 끊기면 조작 버튼이 잠깁니다 (상단 표시 확인).

### 2.4.11 인용구 목록 줄의 본문이 화면과 다르다

목록 줄에 보이는 본문은 **라벨**입니다. 화면에 나가는 본문은 언제나 DB 에서 다시
읽으므로, 화면 쪽이 맞습니다.

역본을 바꾸면 목록 줄도 새 역본으로 다시 읽습니다. 그때 서버 조회가 실패하면 라벨을
비우고 **참조만** 보여 줍니다 — 틀린 글자를 보여 주지 않기 위한 것입니다.

### 2.4.12 인용구에 절 번호가 안 붙는다 / 참조 줄이 안 보인다

**일부러 그렇습니다.** 인용구는 참조를 본문 앞에 붙여 보냅니다
(`고전 1:3 하나님 우리 아버지와…`).

- 절 번호를 또 붙이면 `고전 1:3 3 하나님…` 이 됩니다
- 참조 줄을 또 그리면 같은 것이 두 번 나갑니다

그래서 인용구는 절 번호와 참조 줄을 **끄고** 나갑니다. 항목의 그 두 설정을 켜도
바뀌지 않습니다 (참조 표기를 `끔` 으로 두면 접두사 자체가 빠집니다).

**📖 성경(본문 낭독)은 예전 그대로입니다** — 절 번호와 참조 줄이 나옵니다.

### 2.4.13 같은 절이 화면마다 다르게 나온다

인용구라면 **고쳐졌습니다** (2026-08-20). 네 화면이 같은 글을 보입니다.

그래도 다르면 **화면마다 옛 판이 떠 있는 것**입니다. 화면은 각자 자기 페이지를
들고 있어서, 코드가 바뀌어도 그 창을 새로고침해야 반영됩니다.

| 화면 | 새로고침 |
|---|---|
| 관리자 | `⌘R` / `F5` |
| OBS | 브라우저 소스 더블클릭 → **현재 페이지 새로고침** |
| 강사 모니터 · 프로젝터 | 그 창에서 `F5` |

서버를 재시작해도 이미 열려 있는 창은 다시 읽지 않습니다.

### 2.4.14 저장하면 인용구가 평범한 성경 항목으로 바뀐다 ✅ 고침

**2026-08-20 에 고쳤습니다.** '템플릿 업데이트' 나 '순서 저장하기' 를 누르면 인용구가

봅니다. 새 필드를 넣고 그곳을 잊으면 테스트가 실패합니다.

> 이미 저장해 버려 성경 항목이 된 인용구는 되살릴 수 없습니다 — 표시가 지워졌기

## 3. 데이터 관련

### 3.1 백업은 세 파일이 한 벌이다 ★

`data/songs.sqlite` 만 복사하면 **곡이 0개인 백업**이 됩니다. 최근 내용이 WAL 파일에
들어 있기 때문입니다(실제로 겪음). 반드시 셋을 같은 시각으로 함께 복사하세요.

```bash
TS=$(date +%Y%m%d-%H%M%S)
for ext in "" "-wal" "-shm"; do cp "data/songs.sqlite$ext" "data/backups/songs-$TS.sqlite$ext"; done
```

**한 파일로 뜨려면** `VACUUM INTO` 를 씁니다. WAL 을 합쳐 하나로 만들어 주므로 세 파일을
챙길 필요가 없고, 서버가 켜져 있어도 안전합니다 (검증용 스냅샷에 이 방식을 씁니다).

```bash
node -e "const {DatabaseSync}=require('node:sqlite');new DatabaseSync('data/songs.sqlite',{readOnly:true}).exec(\"VACUUM INTO '/tmp/songs-snapshot.sqlite'\")"
```

검증(곡 수가 나와야 정상):

```bash
node -e "const{DatabaseSync}=require('node:sqlite');const db=new DatabaseSync(process.argv[1],{readOnly:true});console.log('곡',db.prepare('SELECT count(*) c FROM songs').get().c);db.close()" data/backups/songs-YYYYMMDD-HHMMSS.sqlite
```

### 3.4 '글자 크기를 바꿨는데 화면이 그대로다' 는 두 가지다 ★

두 번 다른 이유로 겪었습니다. 증상이 같아 헷갈립니다.

| 원인 | 어떻게 아나 | 해결 |
|---|---|---|
| **측정 창이 1920×1080 이 아니었다** | 출력 화면은 창 크기에 맞춰 배치를 다시 잡는다. 720p 창에서 재면 결과가 어긋난다 | 반드시 **1920×1080** 에서 확인 |
| **autoFit 이 되돌려 깎았다** | 키우면 넘치고, 넘치니 줄여서 결과가 같아진다 | 프로젝터 창은 autoFit 을 껐다. OBS 는 켜 둔 채 '화면 넘김 단위'를 잘게 |

첫 번째는 2026-08-19 에 제가 오진한 것입니다 — autoFit 탓이라고 했는데 실제로는
브라우저 창이 720p 였습니다. **측정은 1920×1080 에서** 하세요.

### 3.5 새찬송가 영어 원제 — 어디서 왔고 무엇이 비어 있나

641곡에 영어 원제(`title_alt`)가 들어 있습니다. 출처는 `data/hymn-en-titles.tsv`
(사용자 노션의 nme.kr 표에서 뽑은 것)입니다.

```bash
node scripts/import-hymn-en-titles.ts
```

미리보기가 기본입니다. `--apply` 가 스냅샷을 먼저 뜹니다. 여러 번 실행해도 결과가 같고,
**이미 적혀 있는 원제는 덮지 않습니다**(덮으려면 `--overwrite`).

**어긋난 구간은 사람이 판정한 값을 씁니다.** 새 631·632·638 은 우리 제목을 기준으로
판정해 넣었고(근거는 `lib/hymn-en-titles.ts` 의 `RESOLVED_SUSPECTS` 에 줄마다 적혀
있습니다), 새 **639 「주 함께 하소서」만 비어 있습니다** — 출처에 그 곡이 아예 없어서
짐작해 채우지 않았습니다.

스크립트를 실행하면 그 표를 근거와 함께 다시 보여 주고, 넣은 뒤 '판정한 것은 채워졌고
나머지는 비어 있다' 를 스스로 검사합니다.

> 두 구간이 **서로 다르게** 밀렸습니다. 631·632 는 한국어 열만 밀렸고(영어는 번호에
> 맞음), 638·639 는 두 열이 함께 밀렸습니다. 그래서 '제목으로 짝짓기' 를 일괄 적용하면
> 631·632 가 틀립니다. 규칙이 아니라 판정표를 둔 이유입니다.

**한국어 제목은 이 출처에서 가져오지 않습니다.** 우리 DB 가 원본입니다(출처에
`정혼한 처녀에세`·`취후기도` 같은 오타가 더 많습니다).

> `title_alt` 는 지금 **저장·백업만 됩니다.** 곡 검색이나 찬양 탭 화면에는 아직
> 나오지 않습니다. 그 기능은 따로 만들어야 합니다.

### 3.2 승인한 가사는 자동 작업이 건드리지 않는다

`lines_source = manual`(검토 탭에서 승인, 찬양 목록의 초록 `승인` 표)인 곡은
줄나눔 재정렬·후렴 병합이 **의도적으로 건너뜁니다.**

그래서 "일괄 정리를 돌렸는데 이 곡만 그대로" 는 대개 **버그가 아니라 규칙**입니다.
그 곡까지 처리하려면 곡을 콕 집어 지정합니다.

```bash
npm run chorus:merge -- --song 3089          # 미리보기 (아무것도 쓰지 않음)
npm run chorus:merge -- --song 3089 --apply  # 적용
```

## 태블릿에서 접속이 안 된다 (2026-08-16 이후)

**증상**: 전에는 태블릿으로 컨트롤 패널이 열렸는데 갑자기 연결되지 않는다.

**원인**: 보안 조치로 **기본 접속 범위가 이 PC 안으로** 바뀌었습니다. 이 앱에는 인증이
없어서, LAN 에 상시 열려 있으면 같은 WiFi 의 누구나 예배 중 화면을 바꾸거나 찬양 가사를
지울 수 있었습니다([보안 감사](SECURITY-AUDIT.md) H-1·H-2).

**해결**: 태블릿을 쓸 때만 엽니다.

```bash
npm run start:lan
```

기동 로그에서 어느 모드인지 항상 확인할 수 있습니다.

```
접속 범위        : 이 PC 안에서만 (태블릿으로 조작하려면 npm run start:lan)   ← 닫힘
태블릿 접속      : http://192.168.1.190:7777/                                  ← 열림
```
