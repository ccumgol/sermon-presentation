# 찬양 자료 형식 — 다른 프로젝트에서 정리할 때

> **언제 읽는가**: 이 앱 밖에서 찬양 가사를 정리해 두고, 나중에 이 앱으로 가져오려 할 때.
> 이미 들어온 곡을 고치는 것은 찬양 탭에서 사람이 합니다.
>
> 이 문서의 규격은 **실제로 돌아가는 코드에서 뽑은 것**입니다 —
> [`lib/lyrics-parser.ts`](../lib/lyrics-parser.ts) · [`lib/praise-parser.ts`](../lib/praise-parser.ts) ·
> [`lib/lang-folder.ts`](../lib/lang-folder.ts) · [`lib/songbook-import.ts`](../lib/songbook-import.ts)

---

## 0. 가장 중요한 규칙 하나

### **줄바꿈이 곧 화면의 줄바꿈이다.**

가사 파일의 한 줄이 프로젝터·OBS 화면의 한 줄로 나갑니다. 그래서 정리할 때
**한 줄에 얼마를 담을지가 곧 화면 디자인**입니다.

- 한국어는 **한 줄 20자 안팎**이 기준입니다 (`DEFAULT_TARGET_CHARS = 20`).
- 문단을 한 덩어리로 두면 이 앱이 자동으로 나눠 주지만, **그건 제안일 뿐**이고
  사람이 검토 화면에서 확인해야 합니다. 미리 나눠 오면 그 단계가 사라집니다.
- 어절 중간에서 끊지 마세요. 숨 쉬는 자리에서 끊습니다.

두 번째로 중요한 것: **UTF-8 로 저장하세요.** (옛 자료가 CP949 인 경우가 있어 읽기는
하지만, 곡집마다 코드에 인코딩을 적어 줘야 합니다.)

## 1. 어떤 통로로 넣을 것인가 — 셋 중 하나를 고릅니다

| 무엇을 하려는가 | 통로 | 형식 |
|---|---|---|
| **새 곡집을 통째로** 넣는다 | 폴더 반입 | `<곡집>/제목 - 번호.txt` (2장) |
| 이미 있는 곡에 **번역만** 더한다 | 번역 폴더 | `언어/곡집id/번호.txt` (3장) |
| 곡을 **구조까지 지정해서** 넣는다 | JSON (API) | `POST /api/songbooks/:id/import` (4장) |

**정리 결과가 곡마다 파일 하나라면 2장**, **구조화된 데이터(표·DB·JSON)라면 4장**을
권합니다. 4장이 제목·원제·저자·저작권·CCLI 까지 담을 수 있어 정보 손실이 없습니다.

## 2. 폴더 반입 — `<곡집>/제목 - 번호.txt`

3,194곡(복음성가집 3종)이 이 통로로 들어왔습니다.

```
찬양자료/
├── 새노래/
│   ├── 주 品에 품으소서 - 1.txt
│   ├── 나의 안에 거하라 - 2.txt
│   └── Above All - 그 무엇보다 - 15.txt
└── 다른곡집/
    └── …
```

### 파일 이름

**`제목 - 번호.txt`** — 맨 뒤의 ` - 숫자` 만 번호로 봅니다.
제목 안에 하이픈이 있어도 안전합니다 (`Above All - 그 무엇보다 - 15` → 번호 15,
제목 `Above All - 그 무엇보다`).

번호가 없는 곡집이면 파일 이름을 제목만 두고 4장(JSON)을 쓰세요 — 폴더 반입은
번호를 요구합니다.

### 파일 내용

절 표시는 **여섯 가지를 모두** 받습니다. 원본 표기를 바꾸지 말고 그대로 두세요.

```
[1절]                 ← 대괄호 라벨
주 품에 품으소서
사랑스런 나의 아이

(후렴)                ← (후렴) · 후렴 · Chorus
사랑합니다 나의 예수님

2                     ← 숫자만 있는 줄
햇살보다 더 따스한

3.온 세상이 변하여도   ← 1. 또는 1) 접두사 (번호는 라벨로 옮겨집니다)
```

| 표기 | 결과 |
|---|---|
| `[1절]` `[Bridge]` | 라벨 그대로 · 종류 자동 추론 |
| `(후렴)` `후렴` `Chorus` | 후렴 섹션 |
| `2` (숫자만 한 줄) | `2절` |
| `3.가사` `3) 가사` | `3절` + 그 줄의 가사 |
| 빈 줄 | 섹션 구분 |
| `---` `***` | 구분선 — 가사로 넣지 않습니다 |

**`1.` 같은 번호는 가사에서 떼어 라벨로 옮깁니다.** 버리는 것이 아니라 옮기는 것이라
화면에 `1.갈보리산 위에` 가 나가지 않습니다.

### ⚠️ 새 곡집은 코드에 한 줄이 필요합니다

지금 폴더 반입기는 **곡집 목록을 코드에 들고 있습니다**
([`scripts/import-praise.ts`](../scripts/import-praise.ts) 의 `BOOKS`) — 폴더 이름, 곡집 id,
짧은 표기, 인코딩. 새 곡집을 넣으려면 그 표에 한 줄을 더해야 합니다.
그게 번거로우면 4장(JSON)을 쓰세요.

## 3. 번역만 더하기 — `언어/곡집id/번호.txt`

**이미 있는 곡**의 번역 가사만 갈아 끼웁니다. 곡을 새로 만들지 않습니다.

```
번역자료/
├── en/
│   ├── hymn_new/
│   │   ├── 1.txt
│   │   └── 305.txt
│   └── hymn_old/
│       └── 405.txt
└── zh/
    └── hymn_new/
        └── 305.txt
```

**파일 이름이 번호인 이유**: 번역판의 제목은 기준이 될 수 없습니다. `Amazing Grace` 와
`나 같은 죄인 살리신` 은 같은 곡이고 곡집마다 표기도 다릅니다. `(곡집, 번호)` 가
사람이 정한 고정 좌표입니다.

### 곡집 id

| id | 곡집 |
|---|---|
| `hymn_new` | 새찬송가 |
| `hymn_old` | 통일찬송가 |
| `many_waters` | 많은물소리 |
| `psalm_praise` | 시와찬미 |
| `chanmi2000` | 찬미예수 2000 |
| `misc` | 기타 |

### 언어 코드

| 코드 | 언어 | 화면에서 고를 수 있나 |
|---|---|---|
| `en` | English | ✅ |
| `zh` | 中文 | 폴더로 넣으면 그 곡에서 보입니다 |
| `ja` | 日本語 | 폴더로 넣으면 그 곡에서 보입니다 |

찬양 탭의 언어 선택은 **한국어·English 만** 내보입니다(2026-08-23 — 넣은 가사가
0줄이었습니다). 다만 **이 폴더 통로는 세 언어를 그대로 받습니다.** 넣으면 그 곡에서는
선택지에 나타나므로 편집할 수 있습니다.

**`ko` 는 받지 않습니다.** 이 통로로 한국어를 넣을 수 있으면 사람이 승인한 가사를
파일로 덮어쓰는 길이 생깁니다. 한국어는 찬양 탭에서 사람이 고칩니다.

### 파일 내용 — 줄 수를 한국어와 맞춥니다

번역 파일은 **한국어 가사와 같은 순서·같은 줄 수**여야 합니다. 짝은 기계가 맞춥니다.

```
[1절]
Amazing grace! how sweet the sound
That saved a wretch like me!

[2절]
'Twas grace that taught my heart to fear
```

라벨(`[1절]`)을 적으면 그 절에 붙이고, 없으면 순서대로 붙입니다.
**줄 수가 어긋나면 조용히 버리지 않고** 어느 절 몇 줄이 남았는지 미리보기에서 알려 줍니다.

```bash
npm run lyrics:lang -- --dir ~/Desktop/Data/Lyrics            # 미리보기
npm run lyrics:lang -- --dir ~/Desktop/Data/Lyrics --apply    # 실제로 넣는다
```

## 4. JSON — 가장 정확한 통로

정보 손실이 없고 코드 수정도 필요 없습니다. `POST /api/songbooks/:id/import`

```json
{
  "mode": "merge",
  "songs": [
    {
      "number": 42,
      "title": "주만 바라볼지라",
      "titleAlt": "Look to Jesus Only",
      "author": "김명식",
      "copyright": "© 1999 …",
      "ccliNumber": "1234567",
      "lyrics": "[1절]\n주만 바라볼지라\n| Look to Jesus only\n\n(후렴)\n…"
    }
  ]
}
```

| 필드 | 필수 | 설명 |
|---|:---:|---|
| `title` | ✅ | 한국어 제목 |
| `number` | | 곡집 번호. 번호 없는 곡집은 비웁니다 |
| `titleAlt` | | **영어 원제** — 새찬송가 644곡에 들어 있는 그 값입니다 |
| `author` `copyright` `ccliNumber` | | 있으면 넣습니다 |
| `lyrics` | | 원문 텍스트 (서버가 구조화) |
| `sections` | | 이미 구조화했다면 이것을 대신 씁니다 |

`text` 필드에 여러 곡을 한 덩어리로 넣는 방법도 있습니다 — 형식은 아래와 같습니다.

```
42. 주만 바라볼지라
[1절]
주만 바라볼지라
| Look to Jesus only

118. 나의 등뒤에서
나의 등 뒤에서 나를 도우시는 주
```

번호가 없는 곡집이면 구분선(`---`)으로 곡을 나누고 `제목:` `저자:` 메타 줄을 씁니다.

## 5. 한/영 병기 — `|` 한 글자

이 교회는 한/영을 함께 띄웁니다. **번역 줄 앞에 `|` 를 붙이면** 바로 위 줄의 번역이 됩니다.

```
[1절]
나 같은 죄인 살리신
| Amazing grace! how sweet the sound
주 은혜 놀라와
| That saved a wretch like me!
```

언어를 명시하려면 `|en` `|zh` `|ja` 로 씁니다. 생략하면 기본 보조 언어로 봅니다.

```
주 은혜 놀라와
|en That saved a wretch like me!
|zh 我曾迷失，今被寻回
```

같은 언어를 두 번 적으면 **뒤에 적은 것이 이깁니다** (사람이 고쳐 쓰다 두 줄이 된
경우가 대부분이라 마지막 뜻을 따릅니다).

## 6. 정리할 때 지켜 주시면 좋은 것

| | |
|---|---|
| **UTF-8** | 인코딩을 코드에 적어 줄 필요가 없습니다 |
| **줄바꿈 = 화면 줄** | 한국어 20자 안팎. 어절 중간에서 끊지 않기 |
| **원본 표기 유지** | `1.` `(후렴)` 을 지우지 마세요 — 이 앱이 라벨로 옮깁니다 |
| **번역은 줄 수를 맞춘다** | 한국어와 순서·줄 수가 같아야 짝이 맞습니다 |
| **영어 원제(`titleAlt`)를 챙긴다** | 영어 가사를 찾을 때 기준이 됩니다 |
| **후렴을 각 절 뒤로 펼치지 마세요** | 이 앱이 절마다 붙여 줍니다. 미리 복사해 두면 중복이 됩니다 |
| **한 곡 = 한 파일**(폴더 통로) | 여러 곡을 한 파일에 담으려면 4장(JSON·text)을 씁니다 |

### 넣기 전에 반드시 미리보기

모든 반입 통로는 **미리보기가 기본이고 `--apply` 를 붙여야 실제로 씁니다.**
수백~수천 곡이 한 번에 바뀌는 작업이라, 해석 결과를 눈으로 본 뒤에 넣습니다.

```bash
npm run praise:check                    # 자료 폴더 점검 (읽기만)
node scripts/import-praise.ts           # 미리보기
node scripts/import-praise.ts --apply   # 실제로 넣는다 (스냅샷을 먼저 뜬다)
```

## 7. 이 앱이 자동으로 해 주는 것 — 미리 하지 마세요

| 하는 일 | 그래서 |
|---|---|
| 자동 줄나눔 (20자 기준) | 한 덩어리로 와도 됩니다 (다만 사람 검토가 필요) |
| 후렴 검출 (절 간 최장 공통 어절) | `(후렴)` 표시가 없어도 찾아냅니다 |
| 후렴을 각 절 뒤로 병합 | 미리 복사하면 중복이 됩니다 |
| 절 간 운율 정렬 | 절끼리 줄 길이를 맞춥니다 |
| 절 번호 표시 (`1. `) | 가사에 `1.` 을 남겨 두지 않아도 됩니다 |
| 영어 원제 물려받기 | 대응곡(`song_links`)에서 가져옵니다 |

**자동 결과는 모두 제안입니다.** 사람이 검토 탭에서 승인해야 확정되고,
승인한 곡(`lines_source='manual'`)은 자동 작업이 다시 건드리지 않습니다.
