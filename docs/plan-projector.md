## 2. 렌더러를 복제하지 않았다

`public/output/output.js` 는 1044줄이고 성경·찬양·교독문·전례문 렌더러가 모두 들어 있다.
복제하면 두 곳이 갈라지고, **한쪽만 고친 것을 예배 중에 알게 된다.**

그래서 프로젝터 페이지는 출력 페이지와 **같은 DOM id** 를 두고 같은 CSS·같은 스크립트를
불러온다. `projector.css`/`projector.js` 는 그 위에 덧칠만 한다.

```
public/projector/index.html   →  /output/output.css + /output/output.js 를 불러온다
                              →  /projector/projector.css (색·크기·막대)
                              →  /projector/projector.js  (줌·반전·전체화면·막대)
```

`tests/unit/projector-page.test.ts` 가 **파일을 읽어** 이 규칙을 지킨다 — 출력 페이지는
의존성 0 이라 import 할 수 없으므로 이 방법밖에 없다.

### layer 는 경로에서 정한다

`output.js` 는 `location.pathname` 이 `/projector` 로 시작하면 layer 를 `projector` 로
잡는다. 쿼리(`?layer=`)에 맡기지 않은 이유는, 사용자가 주소를 손으로 치거나 즐겨찾기에
넣을 때 파라미터가 빠지면 **프로젝터 창이 OBS 화면으로 집계되고** '옛 판이니 브라우저
소스를 새로고침하라' 경고가 엉뚱하게 뜨기 때문이다.

## 3. OBS 와 **동시에 다른 배치**를 쓴다

이것이 이 기능의 핵심이다.

| 화면 | 템플릿 | 이유 |
|---|---|---|
| OBS 송출 | 활성 템플릿 (예: 하단 두 줄) | 카메라 영상 위에 얹는다 |
| 프로젝터 | **'전체 — 성경·찬송 겸용'** 고정 | 벽에 크게. 대비가 낮아 얇은 획이 뭉개진다 |

하나의 활성 템플릿을 모두에게 보내면 둘 중 하나가 망가진다. 그래서 `server/ws.ts` 의
`templateFor()` 가 `projector` layer 에만 다른 템플릿을 보낸다.

`getTemplateOrDefault(-8)` 를 거치므로 **사용자가 '전체' 프리셋을 고치면 프로젝터도
따라간다** — 눈에 보이지 않는 별도 설정을 만들지 않았다.

### 템플릿 편집이 새어 들어오지 않는다

템플릿 탭에서 다른 템플릿을 편집하면 서버가 `style:set` 으로 실시간 미리보기를
뿌린다. **프로젝터는 그 대상에서 뺐다** — 예배 중에 벽에 비친 글이 춤추면 안 된다.
(실측: 활성 템플릿의 글자 크기를 68 → 30px 로 끌어도 프로젝터는 96px 을 유지했다.)

## 4. 주소줄 — 기능이 아니라 **도달 방법**의 문제였다

웹페이지에는 브라우저의 주소줄을 없애는 방법이 **없다.** 있다면 피싱 페이지가 은행
주소를 위조할 수 있으므로, 모든 브라우저가 막아 둔 것이다. 길은 두 개뿐이다.

| 길 | 결과 | 조건 |
|---|---|---|
| **전체 화면 (Fullscreen API)** | 주소줄·제목줄·탭·창 테두리가 **모두** 사라진다 | 사람의 클릭·키 입력에서만 |
| **앱으로 설치 (PWA)** | 애초에 주소줄이 없는 창으로 열린다 | 매니페스트 + 192·512 아이콘 |

### 처음 판은 기능은 있었지만 찾을 수 없었다

첫 구현은 `F` 키와 막대의 버튼만 뒀다. 사용자가 **스크린샷으로 제목줄·출처줄을 빨간
박스로 표시하며 다시 물었다** — 방법이 있어도 도달하지 못했다는 뜻이다. 원인은 둘로 본다.

1. `F` 를 눌러야 하는 것을 몰랐거나,
2. **키보드 초점이 브라우저 쪽에 있어서** `F` 가 페이지에 닿지 않았다. 창을 열고 바로
   누르면 실제로 그렇게 된다.

둘 다 **클릭**으로 풀린다. 클릭은 초점을 페이지로 가져오면서 동시에 사용자 동작이 된다.

### 고친 것

| 무엇 | 왜 |
|---|---|
| **화면을 클릭하면 전체 화면** | 가장 찾기 쉬운 동작. `F` 를 몰라도 된다 |
| 클릭으로 **나가지는 않는다** | 예배 중 실수로 벽에 브라우저 창이 드러나면 안 된다 |
| 막대를 누른 클릭은 제외 | `+` 를 누르려다 전체 화면이 되면 안 된다 |
| **전체 화면 선택을 기억** (`sermon.projector.fullscreen`) | 매주 찾아 누르지 않아도 된다 |
| 기억이 있으면 **첫 클릭·키 입력**에 얹는다 | 사용자 동작 없이는 불가 — 그 동작에 얹는 것이 한계선이다 |
| 마우스 이동은 **세지 않는다** | 브라우저가 사용자 동작으로 인정하지 않아 거절되고, 거절되면 기회를 잃는다 |
| 사람이 직접 나가면 기억을 끈다 | 창 모드로 쓰겠다는 뜻이다 |
| 안내는 **전체 화면이 아닐 때만**, 막대와 함께 | 상시 표시하면 프로젝터 번인 위험 |
| **PWA 매니페스트 + 아이콘** | 매주 쓰는 화면이라면 설치판이 `F` 보다 편하다 |
| 설정 탭에 **프로젝터로 띄우기** 카드 | 방법을 **찾을 수 있는 자리**가 필요했다 |

### 아이콘을 코드로 그렸다

'앱으로 설치' 를 크롬이 제안하려면 매니페스트에 **192·512 PNG** 가 있어야 한다.
그림 파일을 저장소에 넣는 대신 `scripts/make-projector-icons.ts` 가 `node:zlib` 만으로
그린다 — 이미지 도구를 깔지 않아도 되고, **무엇을 그렸는지 읽어서 알 수 있다**
(바이너리는 diff 가 되지 않는다). 검은 바탕에 흰 가로 막대 셋 — 벽에 비친 글줄이다.

> 순서: 프로젝터 버튼 → 창을 프로젝터 화면으로 드래그 → **화면 클릭**
> (매주 쓰면 한 번 **앱으로 설치**)

## 5. 색은 두 토큰으로 정한다

```
--proj-bg / --proj-fg  를 뒤집으면 반전이다
```

`filter: invert()` 를 쓰지 않았다. 그것은 **색상까지 뒤집어서** 회중용 노란 글씨가
파랗게 변한다. 대신 반전할 때 노란색을 같은 계열의 짙은 색(`#8a4b00`)으로 바꾼다 —
노란색은 흰 바탕에서 읽히지 않는다.

### 서버 패치와 싸우지 않는다

서버의 `style:patch` 는 CSS 변수를 `<html>` 의 **인라인 스타일**에 꽂는다. 인라인은
보통 무엇도 이기지만, **CSS 변수는 상속으로 결정된다** — 값을 읽는 `.line-primary` 에서
가장 가까운 조상의 선언이 이긴다. `body` 가 `html` 보다 가까우므로
`body.projector { --primary-color: … }` 가 서버 패치를 가린다.

`!important` 도, 자바스크립트로 인라인을 지우는 짓도 필요 없다. **서버와 화면이 각자
제 일을 한다.**

## 6. autoFit 을 껐다 (중요)

autoFit 은 글이 넘칠 때 화면에 맞춰 줄여 주는 기능이다. 프로젝터에서는 이것이
`+` 버튼과 싸운다 — 키우면 넘치고, 넘치니 되돌려 깎아서 **글자 크기가 바뀌지 않는
것처럼 보인다.** (2026-08-19 에 내가 오진했던 현상이 정확히 이것이다.)

조작자는 벽에 비친 글씨를 직접 보고 있으니, 넘치면 스스로 `−` 를 누르면 된다.
대신 **넘치는 동안 막대에 알린다** — 잘린 글을 눈치채지 못하면 회중이 못 읽는다.

서버가 `autoFitMinScale: 1` 로 보내는 것이 그 구현이다 (`lib/projector-view.ts`).

## 7. 둘째 줄의 바닥을 받쳤다

'전체' 템플릿의 둘째 줄은 42px 이다(첫 줄 96px 의 0.44배). 그 값은 OBS 에서 *둘째
역본*을 곁들일 때를 생각한 것인데, 프로젝터에서 둘째 줄은 곁가지가 아니다 —

- **한/영 병기 찬양의 영어 가사** (이 교회는 미국 한인교회다)
- **교독문의 회중 줄**

대비가 낮은 벽에 42px 로 비치면 회중이 읽을 수 없다. 그래서

| 줄 | 프로젝터에서의 크기 | 근거 |
|---|---|---|
| 둘째 줄 일반 | 첫 줄의 **0.72배 이상** (`max()` 로 받침) | 곁가지가 아니라 읽는 글이다 |
| 교독문 회중 줄 | 첫 줄과 **같은 크기** | 교독문 전용 템플릿이 그렇다 ("색으로만 구분한다") |

`max()` 로 받치므로 템플릿이 이미 큰 값을 주면 그것을 쓴다 — 덮지 않고 아래로만 막는다.

## 8. 배경 그림을 쓰지 않는다

프로젝터가 선명하지 않다는 것이 이 화면이 있는 이유다. 사진 위의 글씨는 회중석에서
읽히지 않는다. 항목이 배경을 지정해도(교독문·찬양) 여기서는 무시한다.

되살리려면 `projector.css` 의 `body.projector #backdrop { display: none }` 한 줄을
지우면 된다.

## 9. 아직 정하지 않은 것

**항목별 템플릿을 프로젝터가 무시한다.** 순서표에서 어떤 항목에 '교독문' 이나
'순서 표시' 템플릿을 따로 지정해도, 프로젝터는 늘 '전체' 로 그린다.

지금은 그것이 요청에 맞다(늘 크고 두껍게). 다만 순서 표시 항목의 붓글씨 리듬처럼
항목 전용 디자인이 프로젝터에서는 사라진다. **항목이 명시적으로 고른 템플릿은 프로젝터도
따르게** 바꾸는 선택지가 있다 — 사용자 확인이 필요하다.

## 10. 실측 (1920×1080)

| 확인 | 결과 |
|---|---|
| layer / 접속 | `projector` · 컨트롤 패널에 초록 점 · **OBS 는 미연결로 남는다** |
| 템플릿 | 활성이 '하단'(68px)인데도 프로젝터는 **96px '전체'** 를 받았다 |
| 굵기 / 테두리 | 800 (템플릿 700) · stroke `none` |
| 배경 그림 | `display: none` |
| 줌 | 96px → 124.8px (130%) · 표시 `130%` · 새로고침 뒤에도 유지 |
| 반전 | 배경 `#fff` · 글자 `#111` · 둘째 줄 `#8a4b00` · 새로고침 뒤에도 유지 |
| 교독문 | 인도자 124.8px = **회중 124.8px** |
| 한/영 찬양 | 한국어 96px/800 · 영어 **69.12px**/600 (42px 아님) |
| 넘침 경고 | 200% 에서 뜨고, 100% 로 되돌리면 사라진다 |
| 템플릿 편집 격리 | 활성 템플릿을 68 → 30px 로 끌어도 프로젝터는 96px |
| 테스트 | 860개 통과 (`projector-view` 7 · `projector-page` 17) |

### 2차 실측 — 주소줄 (2026-08-20 오후)

| 확인 | 결과 |
|---|---|
| 매니페스트 서빙 | `200 · application/manifest+json` · `display: fullscreen` · 아이콘 2개 |
| 아이콘 | `icon-192.png` 530 B · `icon-512.png` 1,939 B · PNG 서명 확인 |
| **실제 클릭 → 전체 화면 호출** | `requestFullscreen` 호출됨 · 기억 `1` 저장 |
| **실제 `F` → 전체 화면 호출** | 호출됨 (합계 2회) |
| 막대 클릭 | 기억을 바꾸지 않는다 (`0` 유지) |
| 거절돼도 화면 정상 | 본문 그대로 · `diag.errors = 0` (거절을 삼킨다) |
| 안내 | 창 모드에서 막대와 함께 뜨고, 전체 화면이면 숨는다 |

> ⚠️ **전체 화면이 실제로 켜지는 것은 이 환경에서 확인할 수 없었다.** 검증에 쓰는 임베드
> 브라우저 창이 Fullscreen API 자체를 막는다(`TypeError: Permissions check failed`).
> 그래서 **호출까지** 확인하고, 브라우저가 허용하는지는 표준 동작에 맡겼다.
> 사용자 환경에서 안 되면 이 줄을 근거로 다시 파야 한다.
