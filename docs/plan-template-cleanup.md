## 1. 요청 1·2 는 사실입니다

### 단일/이중은 아무것도 가르지 않습니다

출력 페이지의 두 렌더러 모두 **자리로만** 역할을 정합니다.

```js
// renderBible
div.className = 'block ' + (index === 0 ? 'line-primary' : 'line-secondary');
// renderSong
div.className = i === 0 ? 'line-primary' : 'line-secondary';
```

역할을 정하는 것은 **내용**(역본을 몇 개 골랐는지, 언어를 몇 개 켰는지)이고 템플릿은
그 자리의 **모양만** 정합니다. 그래서 '단일 역본' 템플릿으로 두 역본을 띄우면 그냥
둘 다 나옵니다 — 사장님이 보신 그대로입니다.

### 본문/찬양도 가르지 않습니다

`TemplateKind`(`bible|song|lower_third|blank|order|reading`)는 **라벨일 뿐**입니다.
템플릿 드롭다운은 `styleTemplates.map` 으로 **전부** 보여 주고 항목 종류로 걸러내지
않습니다.

**증거 — 이미 그렇게 쓰고 계십니다.** `주일예배` 유형의 기본 설정:

```json
{"templates":{"bible":3,"song":3,"order":-9,"text":3}}
```

`id 3` 하나를 성경·찬양·텍스트에 **공용**으로 지정해 두셨습니다. 요청 2 는 새 기능이
아니라 **이미 하고 계신 것을 프리셋 목록에 반영하는 일**입니다.

## 2. 요청 3 — 7개로 줄일 때 깨지는 두 곳

### 현재 11개 → 요청 7개

| 새 프리셋 | 무엇에서 | 없어지는 것 |
|---|---|---|
| 순서표시 | `-9` 그대로 | |
| 교독문 | `-10` 그대로 | |
| 사도신경·주기도문 | `-11` 그대로 | |
| **하단** (성경+찬송) | **사용자 `id 3`** | `-1` 단일 역본, `-2` 이중 역본, `-4` 찬양 이중, `-5` 찬양 단일 |
| **전체** (성경+찬송) | `-8` 찬양 전체화면 | |
| **좌우** (성경+찬송) | `-3` 좌우 분할 | |
| 로우서드 | `-6` 그대로 | |

### ⚠ 깨지는 곳 ① — 기본 템플릿이 지워질 프리셋을 가리킵니다

```ts
export const DEFAULT_TEMPLATE_ID = -2;   // ← 없어질 '설교본문 — 이중 역본'
```

이 값은 네 곳에서 쓰입니다 — 서버 시작 상태(`server/state.ts:27`), 템플릿이 사라졌을
때의 대체(`getTemplateOrDefault`), 템플릿 삭제 후 복구(`routes/templates.ts:140`).
**새 '하단' 으로 다시 잡지 않으면** 프리셋을 못 찾아 목록의 첫 번째로 떨어집니다.

### ⚠ 깨지는 곳 ② — 공백(블랭크) 프리셋이 목록에 없습니다

`-7 공백 (블랭크)` 이 요청하신 7개에 없습니다. 코드에서 이 id 를 참조하는 곳은
정의뿐이고 저장된 순서표도 쓰지 않으므로 **지워도 안전**하지만, 템플릿 드롭다운에서
'공백' 을 고르는 길이 없어집니다. **의도인지 확인이 필요합니다.**

### ✅ 저장한 데이터는 안전합니다

실제 순서표가 참조하는 templateId 를 전부 세어 봤습니다:

```
-9 (순서표시) 8회 · 3 (사장님 사본) 5회 · -10 (교독문) 1회
```

**없어질 `-1`·`-2`·`-4`·`-5`·`-7` 을 참조하는 순서표가 하나도 없습니다.** 지워도
사장님 순서표는 그대로 돕니다.

## 4. 요청 5 — 글꼴을 예배 순서로 옮길 때의 충돌 셋

### ⚠ 충돌 ① — 글꼴 칸은 5개 역할이 함께 씁니다

템플릿 탭의 글꼴 입력은 `TextStyleFields` 안에 있고, 이 묶음은 **주·보조·절번호·참조·
소제목** 다섯 역할에 모두 쓰입니다. 그런데 항목이 정하는 `--item-font` 는

```css
.line-primary  { font-family: var(--item-font, var(--primary-font)); }
.line-secondary{ font-family: var(--item-font, var(--secondary-font)); }
```

**주·보조 두 줄에만** 걸립니다. 글꼴 칸을 통째로 지우면 **참조 표기·소제목·절 번호의
글꼴은 프리셋 값에 고정**되어 손댈 길이 없어집니다. 본문을 명조로 바꿔도 참조 표기는
고딕으로 남습니다.

> **해결책:** 글꼴 칸을 주·보조에서만 없애고 나머지 세 역할은 남기거나,
> `--item-font` 를 다섯 역할 전부에 걸도록 CSS 를 넓히는 것.

### ⚠ 충돌 ② — 영어·그리스어·히브리어는 항목 폰트를 따르지 않습니다

**모든 프리셋**이 공통 헬퍼에서 이것을 갖습니다:

```ts
overridesByLang: {
  en:  { fontFamily: FONT_EN },
  grc: { fontFamily: FONT_GRC },
  heb: { fontFamily: FONT_HEB },
}
```

출력 페이지는 이것을 **인라인 스타일**로 넣습니다(`node.style.fontFamily = ...`).
인라인은 CSS 규칙을 이기므로, 찬양 항목을 '명조' 로 해도 **영어 줄은 `FONT_EN` 그대로**
나갑니다.

라틴 문자에 한글 명조를 씌우지 않는 것은 사실 **바람직한 동작**입니다. 다만
"폰트는 예배 순서에서 지정한다" 가 **한국어 줄에만 적용된다**는 뜻이므로 알고
계셔야 합니다.

### ⚠ 충돌 ③ — 순서표시의 명조를 못 바꾸게 됩니다

`-9 순서표시` 의 명조는 프리셋 코드에 박혀 있어 글꼴 칸을 지워도 **유지**됩니다.
대신 사장님이 그 값을 바꿀 수단이 없어집니다. 순서표시에는 항목별 폰트 선택도
없으니(교독문·전례문에만 있음) 사실상 고정됩니다.

## 5. 요청 7 — 명조는 나눔명조가 맞고, **버그가 있습니다**

두 곳에서 명조 체인이 **다릅니다.**

**순서표시** (`lib/template-presets.ts`, `FONT_KO_SERIF`)
```
Noto Serif KR → Noto Serif CJK KR → BareunBatangOTFPro
→ NanumMyeongjoExtraBold → Nanum Myeongjo → AppleMyungjo → Batang → serif
```
전부 명조 계열입니다. ✅

**교독문·전례문** (`public/output/output.js`, `ITEM_FONTS.serif`)
```
Nanum Myeongjo → Apple SD Gothic Neo → Batang → Noto Serif KR → serif
                 ^^^^^^^^^^^^^^^^^^^ 고딕입니다
```

**2순위가 고딕체입니다.** 나눔명조가 깔린 PC(사장님 Mac 은 깔려 있음, 실측 확인)에서는
문제가 없지만, **나눔명조가 없는 PC 에서 '명조' 를 고르면 고딕이 나옵니다.** 교회 PC 를
바꾸거나 다른 PC 로 옮기면 조용히 드러납니다.

요청대로 **순서표시 체인으로 통일하는 것이 맞습니다.** 한 가지 제약: `output.js` 는
**의존성 0** 원칙(OBS 에서 깨지지 않게)이라 `lib/` 에서 import 할 수 없습니다.
글꼴 문자열을 두 곳에 두거나, 서버가 실어 보내는 방식이어야 합니다.

## 6. 요청 8 — 구조가 맞습니다

지금은 프리셋이 **코드 상수**(음수 id)라 서버가 수정을 거부합니다:

```ts
export function updateTemplate(id, patch) {
  if (getBuiltinTemplate(id)) throw new BuiltinTemplateError();  // → HTTP 409
```

그래서 템플릿 탭이 저장할 때 **강제로 복제**합니다(`draft.isBuiltin` → `duplicateTemplate`).
사장님의 사본 4개가 이렇게 생긴 것입니다.

`getTemplate` 이 지금은 **코드 먼저 → DB 나중**입니다:

```ts
const builtin = getBuiltinTemplate(id);
if (builtin) return builtin;          // ← 여기서 끝나 DB 를 안 본다
```

이 순서를 **DB 먼저 → 코드 대체**로 바꾸면 요청하신 5개 버튼이 자연스럽게 나옵니다:

| 버튼 | 구현 |
|---|---|
| 프리셋 덮어쓰기 | 프리셋 id 로 DB 행을 쓴다 |
| 사본 만들기 | 지금 `duplicate` 그대로 |
| 원본 불러오기 | **DB 행을 지운다** → 코드 상수가 다시 보인다 |
| 프리셋 백업 | `/api/backup` 에 템플릿이 이미 들어 있다 (일부 존재) |
| 프리셋 불러오기 | `/api/backup/import` 활용 |

'원본' 을 따로 저장할 필요가 없다는 점이 좋습니다 — **코드가 곧 원본**입니다.

## 7. 요청 9 — 찬양 3개 언어: 자료는 되고 화면이 제약입니다

### ✅ 자료 구조는 이미 됩니다 (코드 변경 0)

```
song_lines(section_id, line_index, lang, text)   ← 언어 수 제한 없음
```

짝 맞추는 함수도 이미 N개를 다룹니다:

```ts
const group = langs.flatMap((lang) => atIndex.filter((line) => line.lang === lang));
```

성경과 구조가 다른 것은 맞지만(성경은 `primary` + `secondary[]`, 찬양은 `langs[]` 하나),
**찬양 쪽이 오히려 더 유연합니다.**

### 상한은 다섯 곳에 있습니다

| 위치 | 값 |
|---|---|
| `lib/lang-select.ts` | `MAX_LANGS = 2` |
| `server/routes/songs.ts:64` | `langs.slice(0, 2)` |
| `server/routes/plans.ts:163` | `slice(0, 2)` |
| `server/routes/plans.ts:325` | `slice(0, 2)` |
| `src/control/panels/SongPanel.tsx:226` | 자체 중복 로직 |

참고로 성경은 `secondary.slice(0, 2)` 라서 **주 역본 + 2 = 3개**입니다. 찬양을 3개로
맞추려면 `slice(0, 3)` 입니다.

> 곁들여: `SongPanel.tsx:226` 이 `lib/lang-select.ts` 와 **같은 규칙을 중복**으로
> 갖고 있습니다. 제가 어제 공용 모듈을 만들 때 찬양 탭을 안 옮겼습니다. 함께 정리해야
> 두 탭이 어긋나지 않습니다.

### ⚠ 진짜 제약 — 3번째 줄에 스타일이 없습니다

렌더러는 `i === 0 ? primary : secondary` 뿐입니다. **3번째 언어는 2번째와 똑같이
보입니다.** 3단계 역할(tertiary)이 없습니다.

성경 3역본도 같은 한계이고, `overridesByTranslation` 으로 역본마다 색·크기를 달리
줘서 구분합니다. 찬양은 `overridesByLang`(en/zh/ja)으로 같은 일을 할 수 있으니
**실용상으로는 구분 가능**합니다.

또 하나: 3언어 × 2줄이면 **한 화면에 6줄**입니다. 자동 축소가 개입해 글자가 작아집니다
(1080p 실측 기준). `1줄씩` 으로 넘기시는 편이 나을 수 있습니다.

## 8. 요청 10 — 찬양에는 '참조 표기' 와 '소제목' 이 없습니다

### ⚠ 구조 확인

출력 페이지의 `renderSong` 은 이 둘을 **명시적으로 비웁니다**:

```js
setOptional(el.heading, null);      // 소제목 없음
setOptional(el.reference, null);    // 참조 표기 없음
setOptional(el.credit, payload.credit);   // 있는 것은 저작권 표기뿐
```

슬라이드 자료형도 그렇습니다 — 성경은 `reference`·`heading` 을 갖고, 찬양은
`sectionLabel`·`credit` 만 갖습니다.

그래서 찬양의 대응물은 이렇습니다:

| 성경 | 찬양 |
|---|---|
| 참조 표기 (`요 3:16`) | **없음** → 저작권 표기(credit)가 그 자리 |
| 소제목 | **없음** |
| 절 번호 | 있음 — 단 **템플릿이 아니라 내용이 정합니다** (`sectionStart`) |

**찬양 절 번호는 `showVerseNumbers` 를 보지 않습니다.** 그 설정은 성경 절 번호만
가릅니다. 그래서 하단 프리셋을 성경·찬양 공용으로 써도 **부작용이 없습니다** —
요청 3 이 안전한 이유가 여기에도 있습니다.

### ✅ 삭제할 것과 남길 것을 가려야 합니다

- **지울 것**: '표시 옵션' 의 **체크박스** (`TemplatePanel.tsx:422`, `:430`)
- **남길 것**: '글자' 섹션의 **'절 번호'·'소제목' 스타일 묶음** (`:362`, `:364`)
  — 켰을 때 크기·색을 정할 곳이 필요합니다. 이걸 함께 지우면 켜도 모양을 못 잡습니다.

### 구현 방법

렌더러가 `template.behavior` 만 읽으므로, 항목이 정한 값을 **슬라이드에 실어 보내야**
합니다. 교독문·전례문의 `style?: ReadingStyle` 과 **똑같은 방식**이라 전례가 있습니다.

## 9. 요청 11 — 제목 슬라이드: 찬양에 번호가 없습니다

|---|---|---|---|
| 주기도문 | `주기도문` | `주기도문` | ✅ 그대로 |
| 사도신경 | `사도신경` | `사도신경` | ✅ 그대로 |
| 교독문 | `교독문 15. 시편 51편` | `교독문 15, 시편 51편` | 쉼표만 |
| 성경 | `창 1:1-6` (입력한 그대로) | `창세기 1:1-6` 또는 `창 1:1-6` | `referenceFormat` 으로 변환 |
| **찬양** | `만복의 근원 하나님` | `찬송가 1장 만복의 근원 하나님` | ⚠ **번호가 없습니다** |

### ⚠ 찬양 CueItem 에 곡집·번호가 없습니다

```ts
{ type: 'song'; songId: number; songTitle: string; langs: LangCode[]; ... }
```

`songTitle` 은 "곡이 삭제돼도 순서표에 무엇이었는지 남는다" 는 이유로 저장돼 있습니다.
**같은 이유로 곡집·번호도 저장해야** 합니다. 송출할 때 `songId` 로 조회하는 방법도
있지만, 그러면 곡을 지웠을 때 제목만 남고 번호가 사라져 일관성이 깨집니다.

### 결정할 것

- 새 슬라이드 종류를 만들지, `kind: 'text'` 로 보낼지 (제목 전용 스타일을 주려면 필요)
- 제목을 **자동으로** 띄울지(항목 클릭 = 제목 송출), **버튼**을 따로 둘지
  → 자동이면 편하지만, 예배 중 항목을 고르려고 클릭했는데 화면이 바뀝니다.
  현재 항목 클릭은 **펼치기**이고 송출은 `▶` 입니다. 이 구분이 안전장치 역할을 합니다.

#### ⑨ 에서 정한 것

폴더 규약은 **`언어/곡집/번호.txt`** 다. 기존 반입(`제목 - 번호.txt`)과 다른 이유:
그쪽은 곡을 **만드는** 일이라 제목이 필요하고, 이쪽은 이미 있는 곡을 **찾는** 일이다.
번역판의 제목은 기준이 될 수 없다 — `Amazing Grace` 와 `나 같은 죄인 살리신` 은 같은 곡이다.

**`ko` 는 받지 않는다.** 이 통로로 한국어를 받으면 사람이 승인한 가사를 파일로 덮어쓰는
길이 생긴다. 한국어는 찬양 탭에서 사람이 고친다.

**같은 번호의 곡이 둘이면 멈춘다.** `song_entries` 의 PK 가 `(song_id, songbook_id)` 라
같은 번호를 두 곡이 가질 수 있고 **실제로 35건이 그렇다**(많은물소리 301~ 등 실측).
조용히 첫 곡을 고르면 엉뚱한 곡에 번역이 들어가고 예배 화면에서야 드러난다.

**`replaceSectionLines` 로 줄만 바꾼다.** `replaceSections` 는 섹션을 지우고 다시 만들어
`lines_source` 가 한 값으로 뭉개지는데, 그러면 사람이 승인한 한국어가 '자동' 으로 내려간다.
파일에 없는 절은 건드리지 않는다 — 3절만 번역했으면 1·2절은 그대로다.

#### ⑧ 에서 정한 것

**펼칠 때만 띄운다.** 접는 것은 '이제 안 볼래' 이지 '이걸 알려라' 가 아니다.

**항목이 쓸 템플릿을 함께 올린다.** 그러면 제목이 곧이어 나올 본문과 같은 자리·같은
모양으로 뜬다. 활성 템플릿을 그대로 쓰면 앞 순서(순서 표시 등)의 큰 명조가 남아 성경
참조가 엉뚱하게 커진다. 실측: 하단 프리셋의 68px 로 떴다.

**끌 수 있게 뒀다** (기본 설정 → '항목을 누르면 제목 띄우기'). 클릭이 송출을 일으키는
것은 큰 변화라, 예배 중 항목을 살펴보려고 눌렀을 때 화면이 바뀌는 것이 부담스러울 수
있다. 없으면 켠 것으로 본다 — 요청받은 기능이 기본으로 동작해야 하므로 `false` 만 저장된다.

`itemTitle` 은 `describeItem`(목록 라벨)과 **일부러 다르다.** 목록은 조작자가 읽고 제목은
**회중이 읽는다.** 그래서 '교독문 15. 시편 51편'(목록)이 아니라 '교독문 15, 시편 51편'
(화면)이고, 찬양에는 곡집·번호를 앞에 붙인다. 판본(개역개정/개역한글)은 붙이지 않는다 —
회중에게는 뜻이 없다.

**DB 를 뒤지지 않는다.** 항목이 담은 것만 쓴다 — 예배 중 조회가 실패해 제목이 안 뜨는
일이 없어야 한다. 그래서 곡집 표기(`songLabel`)도 항목에 저장한다.

> **옛 순서표의 한계**: 이미 저장된 찬양 항목에는 `songLabel` 이 없어 제목이 곡 제목만
> 뜬다. 사용자가 허용한 형태다("여러 해 동안 주 떠나" 또는 "찬송가 1장 만복의 근원 하나님").
> 새로 넣는 항목부터 붙는다.

#### ⑦ 에서 정한 것

두 탭에는 템플릿 선택이 **아예 없었다** (활성 템플릿을 읽기만 했다). 이 탭들은 순서를
벗어나 급히 띄우는 자리인데 — 설교 중 다른 본문을 찾을 때, 예배 중 곡이 갑자기 바뀔 때 —
그때 화면 모양을 정할 길이 없었다.

고를 수 있는 프리셋은 **셋뿐이다** (`SHARED_PRESET_IDS = [-1, -8, -3]`). 순서 표시·
교독문·전례문·로우서드·공백은 그 항목 전용이라 본문·가사에 쓰면 크기와 배치가 맞지
않는다. **고를 수 있다는 것이 곧 안내**여야 하므로 목록에 넣지 않는다. 테스트가 못박는다.

기본값은 **'템플릿 그대로'**(`undefined`). 처음부터 하나를 골라 두면 이 탭에서 띄울
때마다 템플릿이 바뀌어 예배 순서에서 정해 둔 모양을 덮어쓴다.

송출 시 `template:set` 을 `deck:load` **앞에** 보낸다 — 순서가 반대면 옛 템플릿으로 한 번
그려졌다가 바뀌어 화면이 튄다 (예배 순서 탭의 `sendItem` 과 같은 규칙). 찬양은 송출
경로가 둘(고른 곡·번호 즉시)이라 `sendWithStyle` 한 곳에 모았다 — 두 곳에 적으면
한쪽만 고쳐 '검색해서 띄우면 되는데 번호로 띄우면 안 된다' 가 된다.

#### ⑥ 에서 정한 것

`--item-font` 가 이미 `.line-primary`·`.line-secondary` 에 걸려 있어 **출력 페이지는
고치지 않았다.** 성경·찬양 항목에 `style` 을 실어 보내면 그대로 동작한다.

`ReadingStyle` → **`ItemTextStyle`** 로 이름을 고쳤다. 교독문·전례문 전용이었는데
성경·찬양도 쓰게 되어, 쓰는 곳이 넷이면 이름이 하나를 가리켜서는 안 된다.

**글자 크기는 성경·찬양에서 감췄다** (`showScale={false}`). 본문 길이가 매번 달라
자동 축소가 개입하므로, 크기를 항목마다 주면 요청한 값과 화면이 달라져 무엇이
이겼는지 알기 어렵다. 교독문·전례문은 본문이 정해져 있어 예측할 수 있다.

글꼴 칸은 **주·보조에서만** 없앴다 (§4 충돌 ① 의 권고대로). 절 번호·참조 표기·
소제목은 `--item-font` 가 걸리지 않는 자리라(CSS 가 두 클래스에만 건다) 템플릿에서
정해야 한다. 없애면 켜도 글꼴을 잡을 수 없다.

**§4 충돌 ② 는 사용자 결정대로 그대로 뒀다** — `overridesByLang` 이 en/grc/heb 에
인라인 `fontFamily` 를 넣어 `--item-font` 를 이긴다. 실측 확인: 명조를 골라도
ESV 는 `Inter`, 헬라어는 `SBL Greek` 를 지킨다. **항목 폰트는 한국어 줄에만 적용된다.**

#### ⑤ 에서 정한 것

**모양은 템플릿, 켜고 끄기는 항목.** 크기·색·테두리는 매주 같지만 '이 본문에는 소제목을
띄우자' 는 그 주에 정하는 일이다. 전에는 둘이 템플릿에 함께 있어 한 번 끄려면 템플릿을
고치거나 사본을 만들어야 했다.

값은 **세 갈래**다 — `템플릿 따름` · `켬` · `끔`. 체크박스로 두면 '템플릿을 따른다' 와
'일부러 껐다' 를 구분할 수 없고, 그러면 템플릿을 바꿨을 때 왜 어떤 항목만 안 따라오는지
알 수 없다. `false` 를 기본값으로 채우면 **이미 저장된 순서표가 모두 '끔'** 이 된다.

결정은 **출력 페이지에서** 한다. 컨트롤 패널이 미리 풀어 슬라이드에 담으면 나중에
템플릿만 바꿨을 때 그 값이 따라오지 않는다 (실측 확인: `-1` → `-8` 로 바꾸니 참조가
사라졌다 — 재계산이 된다는 증거).

**찬양에는 참조 표기·소제목이 없다** (`renderSong` 이 비운다). 그래서 찬양 항목에는
절 번호만 보여 준다 — 없는 것을 보여 주면 눌러도 아무 일이 없어 고장으로 읽힌다.

> **작업 중 되돌린 것**: 찬양 절 번호를 `resolveDisplay` 로 넘겼더니 템플릿의
> `showVerseNumbers` 를 보게 되어 **'전체' 프리셋(false)에서 절 번호가 사라졌다.**
> 찬양은 원래부터 그 값을 보지 않고 늘 붙였으므로 사용자가 요청하지 않은 변화다.
> 실측으로 확인해 되돌렸고(항목이 명시적으로 끈 경우에만 끈다) 재발 방지 테스트를 뒀다.

#### ③④ 에서 정한 것

프리셋 **8개** (7개 + 공백. 사용자가 공백을 남기라고 결정):

| id | 이름 | 무엇에서 |
|---|---|---|
| `-1` | 하단 — 성경·찬송 겸용 | **사용자 `id 3` 의 값** (코드로 들어갔다) |
| `-8` | 전체 — 성경·찬송 겸용 | 옛 '찬양 — 전체화면 큰 글씨' (이름만) |
| `-3` | 좌우 — 성경·찬송 겸용 | 옛 '본문 — 좌우 분할' (이름만) |
| `-9` | 순서 표시 — 명조 리듬 | 그대로 |

| `-7` | 공백 (블랭크) | 그대로 |

없어진 것: `-2` `-4` `-5` (하단으로 합쳐졌다). **id 를 다시 쓰지 않는다** —
옛 백업 파일이 엉뚱한 자리에 들어가지 않게 하려는 것이고, 테스트가 못박는다.

`id 3` 의 값을 **코드에** 넣은 이유: 사용자가 실제 화면을 보며 조정한 값이 곧 이 교회의
기준값이다. 코드에 두면 '원본 불러오기' 가 그 값으로 되돌린다. DB 덮어쓰기로 두면
되돌리기가 옛 프리셋 기본값으로 가 버려 뜻이 반대가 된다.

`kind` 는 그대로 뒀다(`bible`/`song`). 라벨일 뿐이고 선택을 제한하지 않으므로 겸용은
**이름으로** 밝힌다. `TemplateKind` 에 `'shared'` 를 넣는 것은 요청에 없던 구조 변경이라
하지 않았다.

①-b 와 ①-c 는 점검 당시 목록에 없던 것입니다. 요청 9(찬양 3언어)를 보다가 **3개 언어를
넣으면 저장이 500 으로 실패**하는 것을 발견해 먼저 고쳤고(격자를 만들어도 저장이 안 되면
쓸 수 없으므로), 사용자가 언어별 편집 화면을 제안해 ①-c 로 넣었습니다.

### §7 요청 9 의 결론 정정

점검에서 "3번째 언어에 스타일 역할이 없다" 를 제약으로 적었는데, 사용자가 **"별 문제가
아니다"** 로 판단했습니다. 그래서 `tertiary` 역할 추가는 **하지 않습니다.** 상한만 3으로
올렸고, 실제로 영어·中文 은 `overridesByLang` 의 글꼴로 구분됩니다(실측: 영어 `Inter`,
中文 `Noto Sans KR`).

### 데이터 구조 이관은 하지 않기로 했습니다

사용자가 "찬양을 `언어-책제목-번호-절`로 성경과 같은 구조로 바꿀 수 있나" 를 물었고,
확인 결과 **찬양은 이미 그 구조**였습니다 (`song_lines.lang` · `song_entries.songbook_id`
· `song_entries.number` · `song_sections.label` + `line_index`, 그리고
`UNIQUE(section_id, line_index, lang)`).

성경이 되는 이유는 구조가 아니라 **정경 앵커**입니다 — `요 3:16` 은 모든 역본에서 같은
것을 가리킵니다. 찬양에는 그런 기준이 없어(새찬송가 1장: 한국어 2줄, 영어 4줄) 구조를
바꿔도 정렬 문제가 사라지지 않고 판단 위치만 옮겨갑니다. 4,396곡 56,497줄을 옮기는 위험을
지고 얻는 것이 없어 **구조를 유지**하기로 했습니다.

폴더(`언어/곡집/번호.txt`)는 **반입 통로로만** 씁니다 (⑨). 송출 시점에 폴더를 읽지
않습니다 — 파일이 지워지거나 이름이 바뀌면 예배 중 화면이 빕니다.
